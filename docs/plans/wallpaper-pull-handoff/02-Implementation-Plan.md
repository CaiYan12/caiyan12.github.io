# 拉绳壁纸挂件：实施计划与技术规格

- 目标仓库：`CaiYan12/caiyan12.github.io`
- 项目类型：Astro 静态博客，GitHub Pages 部署
- 文档用途：供 DeepSeek Harness 实施前调查、拆解任务和验收
- 状态：实施前计划，不代表代码已修改或测试已执行

## 1. 目标定义

在博客视口右上方增加一个常驻的拟物化拉绳挂件。视觉参考随附 原360壁纸素材：`reference.png`、我自绘素材`icon.png`：一根彩色细绳从屏幕上缘垂下，末端挂一件白色短袖 T 恤，衣服上有蓝紫色描边和红色爱心。访客按住 T 恤向下拉，达到阈值并释放时，主站背景壁纸从现有随机壁纸列表中换成另一张。

设计重点不是添加一个换图按钮，而是以简单的物理反馈表达操作：拉动时绳子伸长，释放后挂件回弹，换图过程有短暂过渡。

## 2. 已核对的仓库现状

以下内容来自对仓库当前公开 `main` 的读取。Harness 真正执行前仍须重新读取本地最新代码，确认没有后续改动。

### 2.1 壁纸配置与资源

- 壁纸配置位于 `src/config.ts` 的 `backgroundConfig.images`。
- 当前配置列出 4 张图，路径位于 `/images/bg/`：
    - `/images/bg/pexels-65441.jpg`
    - `/images/bg/pexels-5981771.jpg`
    - `/images/bg/pexels-8561543.jpg`
    - `/images/bg/pexels-30123516.jpg`
- 来源记录位于 `public/images/bg/PEXELS-SOURCES.md`。
- `public/images/random/tb1.jpg` 至 `tb40.jpg` 属于文章封面随机兜底资源，不是背景池。
- 当前背景资源体积从约 0.9 MB 到约 10 MB 不等；不要在初次加载时预加载整个池。

### 2.2 全局布局和背景 DOM

- `src/layouts/Layout.astro` 是全局布局。
- 它在页面内容 slot 之前输出 `.bg-image[data-backgrounds]` 图片节点和 `.bg-image-pattern` 纹理遮罩。
- `.bg-image` 使用固定定位并覆盖视口；纹理遮罩在其上方。实际 z-index、透明度、层叠上下文需要在最新 `src/styles/global.css` 中重新核查，因为文件存在多处同名规则，不能只看第一处定义。
- `Layout.astro` 同时挂载全局控件，例如 Sakura、Pio 和音乐播放器。新挂件应与这些全局控件一样保持在 Swup 内容容器之外。

### 2.3 运行时和 Swup

- `src/utils/theme-script.ts` 是运行时装配入口，所有运行时功能通过 `runtimeTable` 管理。
- `src/utils/runtime/random-background.ts` 中的 `initRandomBackground()` 在首次整页初始化时读取 `.bg-image[data-backgrounds]`，随机选择一个配置路径并写入 `src`，然后通过 `dataset.selected` 阻止重复初始化。
- 现有随机背景只负责初始选图，没有供用户手动切换的入口，也没有排除当前图的逻辑。
- 背景层位于 Swup 容器外，切页不会重建，因而当前背景会跨页面保留。
- `docs/agents/components.md` 规定了主站运行时与 Swup 的初始化协议。新全局控件不应自建另一套 `astro:*` 监听体系，也不应在每次切页时重复注册全局事件。

### 2.4 样式和开发约束

- `AGENTS.md` 要求先复用现有设计资产；新组件颜色、字号、线型、层级应继承 `src/styles/global.css` 已有 token 和约定。
- 修改样式前必须读 `docs/agents/styles.md`，修改全局客户端脚本前必须读 `docs/agents/components.md`。
- 仓库没有必要为该功能引入新的 UI 框架或动画依赖。

## 4. 行为规格

### 4.1 状态模型

建议将交互整理成以下状态，避免拖拽、加载和动画互相竞争：

| 状态       | 含义                            | 允许的操作                             |
| ---------- | ------------------------------- | -------------------------------------- |
| `idle`     | 挂件静止、可交互                | pointerdown、键盘激活、click           |
| `dragging` | 已捕获指针，正在下拉            | 更新绳长与挂件位置；pointerup 判断阈值 |
| `loading`  | 已触发换图，等待候选图片加载    | 禁止重复触发；可取消时需定义取消行为   |
| `settling` | 图片已提交，挂件回弹/背景过渡中 | 禁止重入；动画结束恢复 `idle`          |

触发时序：

1. `pointerdown` 时记录起始坐标，调用 `setPointerCapture`，初始化拖动状态。
2. `pointermove` 只计算向下有效位移，使用 CSS 自定义属性或 transform 更新绳子/衣服。设置最大伸展值。
3. `pointerup` 时判断距离。小于阈值则直接回弹；达到阈值则进入 `loading` 并请求换图。
4. 候选图片加载成功后更新背景并完成过渡；失败则保留旧背景并恢复控件。
5. `pointercancel`、Escape、失焦或 pointer capture 丢失时，安全复位并释放状态。

键盘 Enter / Space 或原生按钮 click 应调用同一个换图入口，避免复制一套选图逻辑。需处理 pointerup 后浏览器可能产生的 click，防止一次拖拽换图两次。

### 4.2 随机候选规则

给定配置数组 `images` 和当前背景 `current`：

1. 过滤非字符串、空字符串和不合法路径。
2. 将路径解析为一致的 URL 表示，避免 `/images/a.jpg` 与完整绝对 URL 比较不一致。
3. 对规范化后的 URL 去重。
4. 排除当前正在显示的背景。
5. 候选项均匀随机选择。建议把 RNG 作为纯函数参数注入，便于单测验证边界和分布索引。
6. 若没有候选，返回无候选结果，不产生虚假切换。
7. 候选载入失败时，不覆盖当前背景；可对剩余候选做有限尝试，每个候选最多一次。

建议把选图逻辑做成纯函数，与 DOM、Image、Pointer Events 解耦。不要只在 DOM 层通过 `Math.random()` 临时拼出路径。

### 4.3 背景更新与过渡

- 候选图先用独立 `Image` 预载，等 `load` / `decode()` 确认资源可用后再提交。
- 不应先将原背景 `src` 改成新图，再等待网络加载，否则会产生空白或旧图消失。
- 背景仍由现有 `.bg-image` 显示，遮罩 `.bg-image-pattern` 不应被移除或改造为第二套背景系统。
- 为实现无明显闪烁的交叉淡入淡出，可在提交新 `src` 前临时保留旧图层，在新图显示后淡出旧图层。临时层必须在结束/异常路径清理，并复用与背景图一致的定位、裁切和透明度逻辑。
- 不能假设组件 scoped CSS 会自动作用到运行时克隆的 DOM 节点；需显式验证样式作用范围。
- 不必预载整个背景池。初始只保留现有随机初始化的一张图，用户触发切换后才载入候选图。

### 4.4 失败和边界情况

- 空池、配置损坏、只有当前一张图：不崩溃、不制造新 URL，给出可访问的状态提示。
- 请求失败或图片解码失败：保持当前图，解除 `busy`，按钮可以再次使用。
- 快速重复拖拽：一个事务完成前拒绝重复请求。
- 用户中途松手、浏览器取消 pointer、切换标签页：控件回到可交互状态。
- Swup 导航、返回/前进：挂件仍在全局 Layout，事件只注册一次，不能因切页而叠加监听器。
- 页面销毁或热更新场景：若运行时添加监听器、动画或临时节点，要有明确清理机制；不保留孤儿图层。

## 5. 视觉与交互验收基准

### 默认状态

- 位于视口右上侧，顶部有细绳悬挂，末端 T 恤完整可见。
- 白色衣服、蓝紫色边线、红色爱心是主要识别元素。
- 尺寸明显小于导航和页面卡片，不形成新的内容区块。
- 静止状态不过分动效化；自然摆动可选，必须尊重 reduced-motion。

### 拖动状态

- 只有按住衣服挂件时才开始拖动。
- 绳长和衣服位置与指针移动同步，向上移动不应触发向下拉伸。
- 达到阈值时有清晰反馈（例如绳子颜色/挂件轻微形变/辅助文字），不能只靠颜色变化。
- 松开后回弹速度自然，避免弹簧动画反复抖动。

### 换图状态

- 仅一次有效释放触发一次换图。
- 新图加载成功后再进行背景交接，不能闪白/闪黑。
- 如果没有其他壁纸或图片加载失败，明确反馈且保持原背景。
- 过渡时长以真实浏览器手感为准，避免拖慢连续操作。

### 响应式与可访问性

- 桌面、平板和窄屏下挂件都不遮挡重要导航或固定控件。
- `Tab` 能聚焦，焦点状态清晰；`Enter` 和 `Space` 能触发。
- 读屏软件能获知控件用途和切换结果。
- 触摸端可操作挂件，页面其余部分继续正常滚动。
- `prefers-reduced-motion: reduce` 下不播放持续摆动和多余弹性效果。

## 6. 测试计划

### 6.1 单元测试

建议测试纯函数与状态决策，不要求测试 SVG 像素：

- 空数组、全非法输入和单图池。
- 多图池过滤当前图片。
- 相对 URL 与绝对 URL 规范化后能正确判断相同图。
- 重复路径去重后不因重复项获得更高概率。
- 注入 `rng=0`、接近 `1`、中间值，确认索引范围正确且不越界。
- 只有一张有效候选且该图为当前图时返回无候选。
- 失败候选不会改变当前背景；有限候选列表不会重复尝试同一路径。

建议放入现有 `src/utils/**/*.test.ts` 范围，让 `pnpm test:utils` 可以覆盖；如果实际测试框架规则不同，以仓库为准。

### 6.2 浏览器冒烟

| 场景           | 操作                         | 期望结果                                       |
| -------------- | ---------------------------- | ---------------------------------------------- |
| 初次加载       | 打开首页                     | 仍按原逻辑随机加载一张背景；没有预取整个图片池 |
| 未达阈值       | 按住并短距离下拉后释放       | 回弹，不换图                                   |
| 达到阈值       | 向下拉到阈值后释放           | 仅换图一次，播放回弹与背景过渡                 |
| 去重           | 连续切换多次                 | 相邻两次不会是同一张（有多张有效图片时）       |
| 图片失败       | 模拟候选请求失败             | 原背景保留，状态恢复，能够再次操作             |
| 并发           | 在加载/过渡时连续触发        | 不重复提交、不积累临时层                       |
| 键盘           | Tab 聚焦后 Enter / Space     | 能换图，焦点反馈可见                           |
| 指针取消       | pointerdown 后 pointercancel | 安全回到静止状态，无换图                       |
| Swup           | 多次页面跳转、前进后退       | 挂件持续可用，单次手势只换图一次               |
| 窄屏           | 移动端视口拖动               | 不挡住导航，页面其他区域仍能滚动               |
| reduced-motion | 模拟系统减少动画             | 无持续摆动/多余弹性，但仍可换图                |

建议通过现有 UI smoke harness 实现，或增加单独 `smoke:wallpaper-pull`；新增 package script 前先检查项目既有脚本约定和测试基础设施。

### 6.3 质量门禁

1. `pnpm check`
2. 新增单测和 `pnpm test:utils`
3. `pnpm build`
4. Build + Preview 下执行主站 UI smoke 和新增交互 smoke
5. `git diff --check`、Prettier 检查、全量 diff 审查

`pnpm build` 包含多项现有测试和构建期联网脚本，务必阅读 `docs/agents/commands.md` 后再执行。对于环境、网络或浏览器导致的失败，清楚区分代码失败与基础设施阻塞。

## 7. 风险与对策

| 风险                         | 后果                           | 对策                                         |
| ---------------------------- | ------------------------------ | -------------------------------------------- |
| 误建第二套壁纸配置           | 两个壁纸池漂移                 | 唯一读取 `backgroundConfig.images`           |
| 误用 `images/random/tb*.jpg` | 背景混入文章封面               | 明确排除该目录                               |
| 修改 `.bg-image` 全局样式    | 现有站点背景透明度/层叠回归    | 优先局部新增，改全局样式必须解释并做全站回归 |
| 忽略 Swup 生命周期           | 重复事件监听、重复触发         | 读 components 约定并纳入 runtimeTable        |
| 直接设置新 src               | 网络加载时出现空白             | 预载成功后提交并交叉淡入淡出                 |
| 预载全部大图                 | 首屏流量、内存和等待时间增加   | 用户触发后只加载候选                         |
| 图片失败后不释放 busy        | 挂件永久不可用                 | 统一 `try/catch/finally` 或等价事务收尾      |
| pointerup 与 click 双触发    | 一次动作换图两次               | 明确区分指针拖动释放与键盘/点击激活          |
| z-index 盲目设大             | 遮挡导航、播放器或可访问性控件 | 核对 `styles.md` 和真实层叠关系              |

## 8. 建议变更范围

初始建议只改以下内容，除非调查证明必须扩展：

- 新增拉绳 Astro 组件。
- 新增挂件运行时模块。
- 修改 `Layout.astro` 挂载该组件。
- 修改 `theme-script.ts` 装配表注册初始化函数。
- 新增壁纸候选纯函数及单测。
- 新增/扩展针对性浏览器 smoke。
- 只有需要全局可复用样式或层级调整时才修改 `global.css`。
- 不修改 `backgroundConfig.images` 现有条目，不替换或转码壁纸资源。

## 9. 推荐实施顺序

1. **复核现状**：检查工作区、读规范和运行时、确认壁纸资源与最新 DOM。
2. **定稿方案**：确定挂件定位、阈值、SVG 结构、背景交叉淡入方式和 smoke 入口。
3. **实现纯逻辑**：壁纸候选规范化、去重、排除当前图和随机选择，先通过单测。
4. **实现组件**：添加可访问的 SVG T 恤挂件与局部 CSS。
5. **实现交互**：Pointer Events、捕获与取消、阈值、忙碌锁、键盘激活、状态反馈。
6. **接入背景**：预载候选、确认成功、提交背景、交叉淡入、清理临时层。
7. **接入全局运行时**：按 runtimeTable 协议一次初始化，确认 Swup 切页无重复绑定。
8. **测试与调优**：单测、类型检查、build、真实浏览器 smoke、窄屏和 reduced-motion。
9. **审查与交付**：完整 diff、无无关改动、列出真实测试结果和遗留限制。

## 10. 完成标准

任务只有在以下条件全部满足时才算完成：

- 挂件外观能识别为参考图中的彩绳 + 爱心 T 恤。
- 向下拖动达到阈值后切换，未达到阈值则回弹。
- 复用唯一现有壁纸池，随机选择均匀，排除当前图。
- 图片加载失败不破坏当前背景，也不会锁死控件。
- 背景切换无明显闪烁，临时节点不会残留。
- 键盘、ARIA、触屏、窄屏和 reduced-motion 可用。
- 不破坏初次背景随机选择、背景纹理层和 Swup 行为。
- 相关单测、类型检查、构建和浏览器验证均有实际记录。
- 未经用户授权不推送、不部署、不合并主分支。
