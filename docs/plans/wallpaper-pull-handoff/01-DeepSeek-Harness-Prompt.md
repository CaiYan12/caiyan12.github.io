## 三、功能规格

### 3.1 外观

- 挂件固定在视口右上侧，从顶部垂下，页面滚动时仍保持在视口位置。
- 造型参考 `reference.png`：多彩或彩色细绳、白色 T 恤、蓝紫色描边、红色爱心。可以用内联 SVG + CSS 绘制，优先简洁、清晰、轻量。
- 衣服轮廓与爱心应在常见桌面分辨率下清晰可辨。挂件默认小巧，不遮挡导航、页面标题、播放器、Pio 或其他重要控件。
- 默认状态只显示悬挂物，不展示常驻大面板。可有轻微自然摆动或 hover 提示，但不能持续抢注意力。
- 动效应延续博客现有视觉风格，不要自行引入一套无关的拟物 UI、玻璃卡片或高饱和装饰系统。
- 桌面端优先还原截图的顶部悬挂位置；窄屏需进行尺寸/位置调整，必要时隐藏非必要装饰，但不要影响页面基本操作。

### 3.2 点击或拖拽换壁纸

- 支持鼠标、触控笔和触摸屏，统一使用 Pointer Events。
- 用户短单击或按住 T 恤挂件后向下拖动，绳子随拖动长度伸展，衣服跟随指针，产生有限、自然的弹性反馈。
- 达到阈值并释放时，触发一次壁纸切换并播放回弹动画。
- 未达到阈值释放、按 Escape、收到 `pointercancel` 或失去 pointer capture 时，挂件回到原位，不换壁纸。
- 拖动距离、阈值、最大伸展距离应有清晰定义，避免 DOM 位移无限增长。初始建议阈值约 70–90 CSS px，实际数值必须通过浏览器手感测试后确定，不得只凭代码猜测。
- 挂件只能在自身交互区域内响应拖动。不要阻止页面其他区域的滚动、选中文字或正常点击。
- 交互过程中加锁，避免连续 pointerup、快速重复操作或过渡未结束时触发并发换图。
- 键盘用户应能聚焦挂件，并通过 Enter / Space 或等价的原生按钮激活方式切换壁纸。键盘激活不要求模拟物理拖拽，但应给出相同的换图结果。

### 3.3 壁纸数据和切换规则

- **唯一壁纸来源必须复用 `src/config.ts` 中现有的 `backgroundConfig.images`。** 不要通过读取目录、硬编码另一份数组、外接 API 或随机图片服务创建第二个壁纸池。
- 壁纸展示继续复用 `Layout.astro` 现有的 `.bg-image[data-backgrounds]` 背景图片层与现有 `.bg-image-pattern` 遮罩；不要绕过当前背景系统，另设 `body { background-image: ... }` 作为并行实现。
- 初次页面加载仍由现有 `random-background.ts` 完成随机背景初始化。新增挂件不得改变首屏随机逻辑、现有背景透明度、纹理遮罩或 Swup 切页时保留当前背景的行为。
- 手动切换时从配置池中均匀随机选择一张，并排除当前正在展示的图片。候选比较需规范化 URL，避免相对路径与绝对路径被当作不同图片。
- 如果池中只有一张有效图片，则不能伪造新图；可保持当前背景并向辅助状态区说明没有其他可切换壁纸。
- 应妥善处理空数组、非法配置、重复路径和图片请求失败。每次操作尝试有限，不得无限重试；某张图片加载失败时不能破坏当前背景。可以在本次操作内尝试其他候选，但每个候选最多尝试一次。
- 壁纸加载完成后再提交视觉切换，避免先清空背景再等待图片网络加载。
- 保持当前来源图片不变。`public/images/bg/PEXELS-SOURCES.md` 是现有 Pexels 背景来源记录；除非本任务确实新增或替换图片，否则不要修改。
- `public/images/random/tb1.jpg` 至 `tb40.jpg` 是文章封面随机兜底资源，不要把它们误当成背景壁纸池。

### 3.4 动画与性能

- 优先使用 CSS transition、Web Animations API 或轻量原生实现，不安装 GSAP、Framer Motion 等动画依赖。
- 背景切换必须避免明显闪白/闪黑。可以预加载候选图片后使用双层短暂交叉淡入淡出，或采用经实机验证不会暴露底色的等效方案。交叉层必须在动画完成后移除，不得越积越多。
- 不要在初次页面载入时预加载整个壁纸池。只在用户明确拉动/激活时加载候选图片，避免把当前多 MB 的图片池全部拉取。
- 动画期间可通过 `requestAnimationFrame` 更新 CSS 自定义属性，但要避免每个 pointermove 都进行多次布局读取/写入。
- 尊重 `prefers-reduced-motion: reduce`：禁用持续摆动和非必要弹性动画，仍保留可用的换图交互与明确状态反馈。
- 图片加载失败、用户连续操作、页面失焦和组件卸载等边界下不得遗留锁定状态、事件监听器或临时节点。

### 3.5 可访问性

- 交互主体应使用原生 `<button>`，或提供完整、等价的键盘与语义支持。
- 设置准确的中文 `aria-label`，例如「向下拉动以更换壁纸」；通过 `aria-live="polite"` 或合适的状态文本反馈成功、无其他壁纸、加载失败等结果。
- 有清晰的 `:focus-visible` 样式，不能只依赖 hover。
- 触摸拖动只在挂件自身处理必要的 `touch-action`，不应禁用整页触摸滚动。
- 不要仅通过颜色表示触发状态。

## 四、推荐实现边界（以当前仓库调查结果为准）

以下是优先方案，不是允许猜测路径的理由。若当前仓库结构不同，应先找等效位置并记录决定。推荐从Context7 MCP 获取最新相关讯息。

- Astro 全局组件入口建议：`src/components/control/WallpaperPull.astro`。
- 交互运行时建议：`src/utils/runtime/wallpaper-pull.ts`。
- 全局挂载建议：在 `src/layouts/Layout.astro` 的 Swup 容器外，与其他全局控件保持一致。
- 初始化注册建议：从 `src/utils/theme-script.ts` 引入挂件初始化函数，并按现有 `runtimeTable` 顺序规则增加一项。由于组件属于全局 Layout、位于 Swup 容器外，通常只需整页初始化一次；**不要自行增加重复的 `astro:*` 监听轨道**。
- 纯函数壁纸候选选择器可放在 `src/utils/` 中合适的位置，并通过现有 `pnpm test:utils` 覆盖。文件放置前先确认现有测试结构。
- 优先用组件局部样式；只有确实需要修改全局层叠时才改 `global.css`，并解释为什么不能局部解决。

### 背景切换的关键实现要求

需要保持现有背景节点和纹理层架构。可考虑：

1. 读取 `.bg-image[data-backgrounds]` 的 `data-backgrounds`，并从当前 `src/currentSrc` 得到当前图片。
2. 对候选列表做路径规范化、去重、排除当前项。
3. 随机挑选候选，使用独立 `Image` 对象预加载并确认成功。
4. 预加载成功后再更新原始背景层；需要交叉淡入淡出时，暂时保留当前图层作为旧图覆盖层，动画结束删除旧层。
5. 失败时保持当前背景不变，恢复控件状态，必要时尝试本次操作中尚未失败的其他候选。

上述步骤是实现思路，不是必须逐字照搬的代码结构。需要实际检查 `.bg-image` 的层叠位置、透明度、`object-fit` 与 `.bg-image-pattern` 关系，保证旧图覆盖层处在正确层次。
