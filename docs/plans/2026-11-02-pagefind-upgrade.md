# Pagefind 第二批独立升级：1.6.0

目标：仅把直接依赖 Pagefind 从 1.5.2 升至精确版本 1.6.0，保留 Svelte、Astro、TypeScript、Prettier、搜索组件和内容收录规则。按已确认的分批方案验收并独立本地提交，不推送或部署。

## 阶段一：基线

- [x] 保存版本、源码摘要与官方发布元数据，确定固定查询集及搜索收录清单。
- [x] 同快照构建旧版 Astro 与 Pagefind Extended，记录全部产物与搜索结果（命中、顺序、标题、摘要）。
- [x] 验收：基线来自当前源码，记录零命中与已知命中，不以 UI 的前 12 条代替完整结果。

## 阶段二：升级与 A/B

- [x] 精确固定 Pagefind 1.6.0，严格安装并核对直接与平台包变化；冻结锁文件安装通过。
- [x] 用相同文章/数据构建，完整生成新版索引与浏览器资源，比较 HTML、JS/CSS、OG 和索引变化。
- [x] 对固定查询集比较完整结果，核对已知文章命中、排除页面、结果链接与摘要；解释排名/分词变化。
- [x] 验收：只有 Pagefind 直接依赖改变；无搜索外的未解释产物变化，已知主要目标保留且无错链；中文检索存在精确性取舍，不作为全部质量提升。

## 阶段三：实机与收尾

- [x] 本地 Chromium 桌面/移动验证中文、英文、组合关键词、空查询、无结果、忙碌提交、主模块加载失败提示、搜索结果切页与后退恢复。
- [x] 验证新索引及浏览器资源加载完整，无混版/本站缺失资源或非预期页面异常；检查截图。
- [x] 运行项目 check、公式保护与格式门禁，独立评审并同步 CHANGELOG 和构建/命令文档。
- [x] 独立本地提交，确认工作区状态；不推进第三批。

## 方法与证据

日志与辅助脚本存放 `output/pagefind-upgrade/`。两侧保持文章及数据快照不变，使用 `NODE_USE_ENV_PROXY=1`，运行 `pnpm exec astro build`、`node scripts/inject-buddha-banner.mjs`、`pnpm exec pagefind --site dist`；不运行网络快照刷新链。保留 HTML 原始 hash，仅对已有随机推荐侧栏另做归一化比较。使用真实浏览器 Pagefind API 采集完整结果，并验证本站自定义 Search.svelte；默认 Component UI 的修复不直接算作本站收益。

官方依据：[1.6.0 发布说明](https://github.com/Pagefind/pagefind/releases/tag/v1.6.0)，特别是 Extended 构建中文分词改用 ICU4X；[JavaScript API](https://pagefind.app/docs/search/)。实际改善以本轮 A/B 为准。

## 执行结果

2026-11-02，Windows / Node 24.18.0 / pnpm 10.26.2，起点 `7bcea01474549f76ee4df45e084a7772ddd63388`，工作区初始干净。第一批检查器的本地提交保持不变，本轮不发布两批中的任何一批。

### 安装与产物

- 将 `pagefind` 从安装版 1.5.2（原声明 `^1.4.0`）改为精确 `1.6.0`；执行严格 peer 安装与 frozen/offline 安装，均 exit 0。直接依赖快照对比只有 Pagefind 改变，锁文件只更新该包与七个平台可选包，未混升 Svelte、检查器或样式工具。
- 两侧均实际执行本文的构建命令，Astro 各生成 229 页，HTML 总量均为 230；Extended CLI 的语言均为 `zh-cn`，索引文档均为 28。CLI 分词计数 9911→47574，是分词单位变化，不表示新增文章。
- 总产物 1308→1322 项；Pagefind 目录 53→67 文件，总字节 1,565,792→2,125,931。该目录包含本站未使用的默认 UI 资源，不等于访客单次查询下载量；没有据单次构建耗时宣称性能提升。
- Pagefind 目录外没有文件增删；所有非 HTML 文件逐字节相同（含站点 JS/CSS 与 OG）。146 个 HTML 原始 hash 有差异，仅移除既有随机推荐侧栏后全部相同。原有 260 个 `src` 文件摘要全部保持，未改文章、组件、收录属性或排序配置。

### 搜索 A/B 与语义变化

- `capture.mjs before/after` 分别启动本地 preview，用 Chromium 的真实 Pagefind 模块执行 `search(null)` 枚举文档，并对固定 31 组查询收集每个 `results.data()` 的 URL、标题和摘要；没有截为 UI 的 12 条。原始快照 `search-before.json` / `search-after.json`、比较 `comparison.json`、逐项变化证据 `semantic-evidence.json` 均保留。
- 收录文档的 URL 集合与标题完全一致，Nice Books、游戏与独立 AI News 页面未进入结果集合。28 篇公开索引 `content` 中 3 篇有空白规范化变化，去除空白后全部一致，没有非空白内容丢失。每个新结果都指向实际存在的构建页面，标题也与该页面索引元数据一致。
- 31 组查询中 6 组命中集合变化、18 组 URL 顺序变化（含集合变化）、29 组摘要变化。Astro、TypeScript、Linux、费用贬值等已知主要目标保留；无结果探针仍为零命中。排名及摘要变化不一律算改善。

Pagefind 的官方查询实现使用浏览器 Intl.Segmenter，词匹配包含前缀及回退匹配；新版索引的 ICU4X 分词改变了词表。上述实测与这类机制相符，但本轮未逐项修改权重或排除内容来“修齐”结果，也不把检索精确性取舍掩盖成统一提升。官方实现说明：[查询分词](https://github.com/Pagefind/pagefind/blob/main/pagefind_web_js/lib/coupled_search.ts)、[词匹配](https://github.com/Pagefind/pagefind/blob/main/pagefind_web/src/search.rs)。

旧新索引均包含部分相关链接和“热门推荐”文字；例如费用文章标题能在其他文章的链接区被检索到。这是旧索引已存在的内容边界，本轮保留原规则；收录文档不变不代表每一命中都来自正文。

### UI 与故障验证

- 新旧两侧各用独立 Chromium context 验证 1280×900 / 390×900：URL 预填中文查询，英文和中文组合查询，Enter 提交，空查询清空，无结果文案，点击结果 Swup 切页与后退后恢复关键词和结果。正常流程的 pageerror、本站 requestfailed 均为零，文档宽度等于视口；截图已查看。
- 忙碌测试通过可控路由 gate 挂起搜索资源，确认 disabled / aria-disabled；更换输入并重复 Enter 后释放 gate，结果仍属第一轮查询，既有重复提交防护保持。
- 单独中断 `/pagefind/pagefind.js`，两版都显示现有“搜索暂时不可用”文案，无未捕获页面异常。此故障与正常页面失败请求统计分开。
- 分片故障在每版的全新 context 中中断首个 `index/*.pf_index` 请求一次。`retry-detail.json` 对照使用完整旧 `index-before/` 目录（entry version 1.5.2）与真实新 1.6.0 目录，未混用资源：两版第一轮都显示“没有找到”、0 条，没有通用错误提示；第二次提交旧版仍 0 条，新版恢复 12 条（UI 展示上限）。这证明新版在该场景可再次查询恢复，**不表示首轮失败已有错误提示或自动重试**。首轮无结果的既有限制未修。
- preview 和浏览器均在 finally 中关闭，旧索引备份保留在证据目录。没有禁用或修改播放器等第三方组件来制造成功结果。
