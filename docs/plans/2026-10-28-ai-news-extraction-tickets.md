## 2. 已确认的粒度与依赖

1. **T1 独立应用的本地阅读闭环**。无阻塞。交付可独立安装、构建并在项目基路径下浏览列表、打开详情和返回的应用。
2. **T2 旧用户状态继承与兼容回写**。被 T1 阻塞。交付旧记录和设置在新应用可读、可操作、可回写，恢复旧产物后仍可读的完整流程。
3. **T3 实时订阅、快照与通用阅读回退**。被 T1 阻塞。交付实时获取、失败回退、来源提示和内容安全边界在独立应用中保持原有行为。
4. **T4 全部模板、设置与导航过渡对齐**。被 T1 阻塞。交付桌面和窄屏下的完整阅读体验，覆盖已确认的模板矩阵与交互。
5. **T5 原地址上线、双向入口与失败恢复**。被 T2、T3、T4 阻塞。交付在原公开地址实际运行的新项目和可执行的恢复方案。
6. **T6 主站旧实现清理与独立发布复核**。被 T5 阻塞。交付主站退出日报构建职责、再次发布也不破坏日报入口的结果。
7. **T7 可复现的维护交接与迁移结案材料**。被 T6 阻塞。交付后续维护者能在独立项目中接手的配置、说明、部署证据和遗留事项。

依赖关系：T1 → T2/T3/T4 → T5 → T6 → T7。T2、T3、T4 在逻辑上不互相阻塞；是否并行实施另由后续执行方式决定，不能把此图当成多代理执行授权。

目标仓库：`CaiYan12/ai-news`。

#### Parent

[SPEC：将 AI日报迁为独立项目并保留原访问入口](https://github.com/CaiYan12/ai-news/issues/1)

#### What to build

让读者在独立构建的 AI日报中，从列表进入单期详情并返回，同时让维护者不依赖主站源码即可安装、检查和构建应用。以现有稳定 React 应用为迁移起点，保留全部功能代码和定制模板；此票先证明最窄的可用阅读闭环，不裁剪其他功能来换取通过。

#### Acceptance criteria

- [ ] 采用已确认的 Vite + React + TypeScript 路线，保留应用运行时依赖版本起点，核实新增工具的引擎兼容性并形成可复现锁文件；独立安装、类型检查与生产构建通过。
- [ ] 新项目不读取主站源码或旧哈希资源即可运行；标题为“AI 日报”，原图标和返回主站入口保留，样式与静态资源正确适配 `/ai-news/` 基路径。
- [ ] 用可重复的订阅数据完成列表、详情、返回和详情直接打开的浏览器演示；既有 hash 与 GUID 规则保持，内置快照公开地址不重复拼接项目路径。
- [ ] 保留五套模板及原有应用功能，不以临时样式、空详情、占位数据或删减功能代替迁移；完整验证分别由后续票交付。
- [ ] 新启动入口不因挂载方式变化新增重复监听、刷新任务或重复导航；无 JS 说明和 JS 接管行为可验证。
- [ ] 留存旧主站基线与相同数据的新旧对照入口，记录来源仓库和基准提交；主站服务、旧应用和发布流程保持可恢复，本票不执行公开发布或主站清理。
