# SPEC：主站 UI 缺陷修复（T0–T3 四批）

- 日期：2026-09-21
- 状态：待批准（seams 待确认；Q43 已闭结、Q48 只剩一个二选一，**尚不满足开工条件**）
- 证据登记册：`docs/ui-adjust-0921.md`（本 spec 只记耐久意图，具体行号与实测数值在那份文件里，避免行号漂移）
- 上位决策：`docs/adr/0002`（独立壳）、`0003`（文章页标题分叉）、`0004`（还原度政策三条款）

## Problem Statement

访客在若干处拿到比站点意图更差的体验，而站点自己的文档与代码已经互相矛盾：

- 文章页标题被单行省略号截断，桌面就会丢字，窄屏丢掉约六成——canonical 页面上内容被无声摧毁。
- 剧透块声明自己是按钮、可被键盘聚焦，却只对鼠标点击有反应。
- 站内搜索与日报阅读页在 JS 未启动时是一整块空白，看起来像坏站。
- 桌面 logo 的落点（导航站页）禁用了浏览器缩放、把中文标注为英文语言、且没有任何标题与地标结构。
- 移动端全屏菜单已经计算出「当前页态」，却没有任何样式消费它；「附加功能」这一组连算都没算。
- 搜索框自己关掉了全局焦点环，且搜索进行中按钮仍可重复点击。
- 次要文字色有五个来源，其中三处对白底只有 2.78:1；标签药丸六色配白字全部不达 AA。
- 一批「写了不生效」的规则与若干条已经失真的文档约束，会让后续任何一次会话（含本会话自己）据此做出错误推断。

## Solution

按风险与依赖切成四批修复，每批独立可回滚、独立停下预览；观感让步类只挑无争议杠杆，品牌色与原版节奏一律保守：

- **T0** 功能与可达性缺陷修复（标题截断、剧透块键盘、无 JS 地板线、独立壳导航站页、当前页态、搜索框焦点与禁用、备案域名）。
- **T1** 一致性与度量修复（次要文字单源化、全死规则清理、站点标题降级与层级拉平、命中区、贡献日历标签、原版正文按钮家族、等宽数字保险、三族缩略图圆角）。
- **T2** 死规则与文档失真更正（根字号基线、`.header-ticker` 死块、`100dvh`、404 标题与分页元数据、AGENTS.md/README 更正 + 「锁选择器不锁行号」写作约定）。
- **T3** 对比度与品牌让步（绿色瞬时态补非颜色辅助、药丸保白字换深色 token、z-index 三处真实风险 + 关系表入文档）。

## User Stories

访客（桌面）
1. As a desktop reader, I want a long article title to be shown in full on the article page, so that I can confirm I opened the post I meant to.
2. As a desktop reader, I want card titles on list pages to stay one line each, so that the archive and index keep their scannable rhythm.
3. As a desktop reader, I want the article header's black marker bar to stay attached to the title block, so that the page still looks like the theme I know.
4. As a desktop reader, I want secondary text (dates, counts, descriptions) to be legible against white cards, so that I do not have to squint at metadata.
5. As a desktop reader, I want tag pills to stay six-colour coded, so that the tag cloud keeps its original look.
6. As a desktop reader, I want tag pill labels readable at 11px, so that I can read the tag name and its count without contrast strain.
7. As a desktop reader, I want the site title to remain visually identical after its heading level is demoted, so that the header looks unchanged.
8. As a desktop reader, I want the click-effect words and the loading overlay to stop covering the lightbox and the toasts, so that overlays appear in the order I expect.

访客（移动）
9. As a phone visitor, I want the title of an article to wrap onto multiple lines instead of being cut, so that I can read it without zooming.
10. As a phone visitor, I want a visible indication of which page I am on inside the full-screen menu, so that I know where I am in the nav.
11. As a phone visitor, I want the slideshow slide selectors to be easy to hit, so that I do not mis-tap.
12. As a phone visitor, I want to be able to pinch-zoom the navigation-station page, so that I can read small text with my own browser controls.
13. As a phone visitor, I want the tag pills still comfortable to tap at narrow widths, so that the tag and category pages remain usable with a thumb.
14. As a phone visitor, I want the modal dialog on the navigation-station page to fit my actual visible viewport, so that its bottom controls are not cut off.

访客（键盘与读屏）
15. As a keyboard user, I want to open and close a spoiler block with Enter or Space, so that I am not limited to the mouse.
16. As a keyboard user, I want a visible focus ring on the search field, so that I can see where I am.
17. As a keyboard user, I want the search field to remain in the tab order, so that the site is operable without a pointer.
18. As a screen-reader user, I want each page to expose exactly one top-level heading, so that the heading outline is not ambiguous.
19. As a screen-reader user, I want the current page marked semantically in both the desktop dropdowns and the mobile menu, so that navigation reports my position.
20. As a screen-reader user, I want a spoiler to announce its expanded/collapsed state, so that I know whether the hidden text is revealed.
21. As a screen-reader user, I want the navigation-station page content to be announced as Chinese and to have a main landmark, so that it is not read with the wrong pronunciation model.
22. As a screen-reader user, I want the 404 page to have a heading, so that the "page not found" state is discoverable by heading navigation.
23. As a screen-reader user, I want secondary text colour contrast to pass AA, so that metadata is legible regardless of my vision.
24. As a low-vision user, I want hover/focus colour changes to be accompanied by a non-colour cue, so that state changes are not communicated by colour alone.
25. As a user who prefers reduced motion, I want no animation that lacks a reduced counterpart, so that my preference is honoured.

访客（无 JS / 慢网）
26. As a visitor with JavaScript disabled, I want the search page to explain that search needs JS and offer tag/category/archive entry points, so that the page does not look broken.
27. As a visitor with JavaScript disabled, I want the daily-report page to explain it is still loading and that an offline snapshot exists, so that I understand the empty state.
28. As a visitor on a slow connection, I want the pre-hydration content to be replaced cleanly on hydration, so that nothing lingers or flashes.

站长（单人开发者）
29. As the site owner, I want each fix batch to stop for my own browser preview before anything is committed, so that I stay the judge of visual changes.
30. As the site owner, I want one commit per fix item, so that a single disagreeable change can be reverted without collateral damage.
31. As the site owner, I want the brand colour to remain #00c000 for decoration and fills, so that the site keeps its identity.
32. As the site owner, I want the original theme's own interaction states restored rather than invented, so that fidelity and quality do not trade off.
33. As the site owner, I want a machine-checkable proof that "only the intended things changed", so that I do not have to eyeball 24 pages.
34. As the site owner, I want the fragile layout relationships (header height, backtop offset, calendar grid) untouched by these fixes, so that documented landmines stay buried.
35. As the site owner, I want the pill colour decision visible as a data table, so that I can pick a darkening level instead of guessing.

后续会话与维护者
36. As a future agent session, I want the docs to stop asserting things that are false about the code, so that I do not make wrong inferences again.
37. As a future agent session, I want constraints anchored on selectors rather than line numbers, so that references survive concurrent commits.
38. As a future agent session, I want the intentional divergences from the original theme recorded as decisions, so that I do not "helpfully" unify them back.
39. As a future agent session, I want the fidelity policy to state which of its three clauses wins when they conflict, so that contrast-versus-authenticity questions have an answer.
40. As a maintainer, I want the dead rules deleted rather than commented out, so that the stylesheet stops lying about what is in effect.
41. As a maintainer, I want the root font-size baseline stated explicitly, so that no one reasons from a rule that never applied.
42. As a maintainer, I want the stacking relationships written down as a table, so that a future z-index change does not quietly invert the player or the lightbox.
43. As a reviewer, I want the evidence register kept separate from this spec, so that the spec stays valid after the code moves.

## Implementation Decisions

**批次与停止点（Q50-C）**：代码四批各一批一停预览；文档更正单独一停。任何一批未通过预览，不进入下一批。

### T0（功能与可达性）

- **文章页标题**：把 `.post-header h1` 从与列表卡共享的那条组合规则中摘出，改为自适应高度、允许换行、行高约 1.34、字号沿用实测生效值，并加 `text-wrap: balance`。列表卡 `.post-list .post-header h2` 明确保持单行省略——**同类名下故意分叉**，依据 ADR-0003。文章页标题元素补 `title` 属性作为桌面 hover 兜底。`.post-header` 的左侧黑色标记条本轮不动（拉长属已接受代价）。
- **剧透块**：键盘激活与现有点击共用同一处事件委托（遵守 Swup 重初始化协议，不新增第四种初始化轨道），并同步 `aria-expanded`。`role="button"` + `tabindex` 的现有输出结构不变，**本轮不改 remark 插件的 DOM 契约**（因此不触发 content layer 缓存问题）。按下态沿用原版钦定的红色。
- **无 JS 地板线**：两个 `client:only` 岛屿各加一层 `slot="fallback"` 静态说明（Astro 6 已无 `fallback` prop；该机制只在 `client:only` 下有文档，且由服务端渲染进岛屿内部，水合后被替换——Svelte 5 侧的历史缺陷在本项目锁定的集成版本中已修复）。术语依「无 JS 地板线」定义：只承诺说明与站内入口，不承诺降级功能。`server:defer` 因本站为无 adapter 的静态输出而不可用；Pagefind 是纯浏览器索引，真降级搜索在 GitHub Pages 上不可能，故明确排除。
- **独立壳导航站页**：按 ADR-0002 只做就地最小修正——语言标注、解除禁缩放、把全局 `* { font-family }` 收窄到终端风格元素、内联品牌色统一到站点 token、正文容器补主站正文字体；头像块外包一层 `<a>` 作为返回主站入口并补可见焦点样式；favicon 两处一律不动。该页继续作为独立壳存在。
- **当前页态**：补齐「附加功能」组在桌面下拉与移动菜单两处的 current 计算（沿用既有协议：父项 current 由子链接 `some()` 判定），并新增消费 `.current` 的移动菜单样式，图案照抄原版桌面菜单的当前项表现（绿色下边框 + 绿色文字）。依据术语「当前页态」：**算了就必须有人画**。
- **搜索框**：移除组件内对全局焦点环的抑制；搜索进行中禁用提交入口并提供禁用态样式，避免并发查询导致结果乱序。
- **备案链接**：域名换到现行官方站点。当前备案号为空，该块不渲染，属预防性修复。

### T1（一致性与度量）

- **次要文字单源化**：全站 meta/日期/计数类文字收敛到单一 `#666`（对白底 5.74:1）。这会用 ADR-0004 的「漂移更优则转正」条款，把原版的 `#999aaa`（2.78:1）替换掉；`--colorful-muted` 自称达 AA 的注释一并按实测更正。
- **站点标题降级**：`Navbar` 中的站点标题从 `<h1>` 降为非标题元素，计算样式需逐条重指（含 681–1100px 活动带的复查，这是文档已锁的脆弱区）；侧栏部件标题层级与文章页跳级一并拉平。要求视觉逐像素不变。
- **命中区**：只处理独立控件——药丸仅在窄屏断点下扩大垂直内距（桌面保持原值，因为该盒值与原版逐字节相同且被五处 DOM 共用）；幻灯片指示点用伪元素扩大热区而外观尺寸不动（10×10 本身就是原版值）。**内联在文字流里的面包屑与页脚链接不动**，依据 WCAG 2.5.8 的 Inline 豁免。
- **贡献日历标签**：标签字号提到桌面 11px / 窄屏 10px。已证其与格子几何不耦合（方形由整体 `aspect-ratio` 与 subgrid 构造保证，标签在独立轨道），但需与首列宽度变量及其硬编码副本同步改；验证点是月份行的裁切与周几列的外溢。不得触碰已锁的滚动容器内距与入场方向。
- **原版正文按钮家族**：把原版缺失的基态 / hover / 按下三态搬回，仅作用于正文中真实的按钮元素；`.spoiler` 因其藏字语义继续使用现有暗底样式。实施前先枚举站内真按钮，避免误伤。
- **等宽数字保险**：给日期与计数类加 `tabular-nums`。已实测该字体西文数字本就等宽、此声明当前为空操作，仍按决策作为换字体保险保留，因此**不作为验收判据**，只要求无回归。
- **三族缩略图圆角**：仅修正图片圆角大于其卡片圆角这一处真 bug；三族宽度差异不动（分属不同页面，从不并排）。

### T2（死规则与文档）

- **根字号基线**：删除从未生效的 13px 根字号规则，并显式声明百分比基线，把「本站根字号 = 浏览器默认」钉成可读事实。不采用「启用 13px」方案：Tailwind 的间距与字号表以 rem 为单位，改动等同全站重排。
- **`.header-ticker` 死块删除**，并在文档中补两条认知约束：头部轮播只有一条实现；**Tailwind v3 的 `@layer` 是构建期指令、产物中不存在级联层，冲突按「特异性 → 源顺序」判定**（本会话曾因误判该机制得出错误结论）。
- **断点**：仅删除已被证明无效的网格声明；680/681 经核实自洽、非缺陷；768 的双断点分工不同，合并属重构，另案。
- **弹窗高度**改用同时兼容旧浏览器的视口单位写法。
- **文档更正**：按证据登记册逐条修正 README 与 AGENTS.md（版本、脚本清单、计数、机制归因、ADR 数量等），并新增写作约定：约束以选择器与路径为锚点，行号仅作辅助且必须标「约」。带日期的历史实测数字保留原样。
- **独立壳阅读模块的文字尺寸契约补一句适用域**：原审计把一处 11.9px 判成违反「辅助文字 ≥13px」，实测该元素是 `aria-hidden` 的装饰字形，不承载可读信息 → 契约改为只约束文字内容，装饰字形除外。代码不动，此为对该模块视觉契约的一次澄清而非让步。

### T3（对比度与品牌让步）

- **绿色**：`#00c000` 保持不动。已核实全部「绿字」落点都是瞬时态或装饰伪元素，默认态文字为 21:1。改为给这些瞬时态附加一层不依赖颜色的辅助（下划线或字重），其中字重方案必须先实测宽度跳动。
- **药丸**：保持白字，替换六个背景 token 为同色相压暗值（候选三档已在证据登记册中列表，全部实测过白字对比度与六色可辨性）。**唯一未闭合的子决策已收窄为二选一**：琥珀色保白字就必须降到原亮度约 63%（实测边界 `#a16a00` = 4.59、`#aa6600` = 4.56；`#b06900` 只有 4.32 不达标），否则单独给琥珀用黑字（现状黑字 10.93，是六色里唯一「黑字远优于白字」的一格）。改动集中在六个 token 定义处，不触碰 `nth-child` 轮换、计数徽标与当前项的源顺序。
- **z-index**：只修三处真实风险（跳过链接与常驻播放器的层级余量仅 1、点击特效浮层高于灯箱、加载遮罩高于提示），其余 22 个散值不动；同时把「谁必须位于谁之上」写成文档表格，防止后续重排踩回退。

### 依赖与前置（未满足则不得开工）

1. 决策文档与 ADR 先落一条提交，形成可回退的「动工前」边界。
2. 在干净工作树上采集**改前样式指纹基线**（24 页逐元素，含伪元素），否则 T1/T2 的「零意外差异」判据无法成立。
3. 并发会话状态确认：本会话期间仓库 HEAD 已被其他会话推进两次，需确认无并行编辑后再动共享样式表。
4. 子决策：Q43 已闭结（那个 11.9px 元素实测是 `aria-hidden` 的装饰星标，不承载信息 → 改契约不改代码，见 T2 末条）；Q48 只剩「琥珀压棕 vs 琥珀单独黑字」的二选一，留到 T3 批次预览时定。
5. 前置 3 的当前状态：最近一次检查 HEAD 仍停在 `2de963e`、工作树只有本次的文档改动，即并发会话暂未活动；开工前需再确认一次。

## Testing Decisions

**好测试的定义**：只断言外部可观察行为——真实渲染后的计算值、几何尺寸、键盘操作结果、可访问性树属性——绝不断言 CSS 源文本、类名字符串或行号。所有断言针对构建产物 + 预览服务器（`build && preview`），不使用 dev 服务器（dev 下看板娘不渲染、懒加载样式被误删，均为已知假象来源）。

**缝隙（seams）**：

- **缝隙 A（新增，单一入口）**：一个 Playwright 冒烟脚本，按现有 `test:fancybox` / `smoke:nice-books` 的同一形态与调用约定编写，接收同一类 base URL 环境变量，覆盖 T0 与 T1 的绝对属性断言：文章页标题在五个宽度下不被裁切、`.spoiler` 键盘可开关、无 JS 上下文中降级说明存在且开 JS 后被替换、移动菜单当前项的计算色与边框、搜索框焦点可见与按钮禁用、导航站页的语言与缩放与返回入口、药丸与幻灯片点的命中几何、日历标签字号与裁切。理由：这是能覆盖全部本轮改动的最高一层，且仓库已有同形态先例可循。
- **缝隙 B（复用，零新增）**：`upgrade-style-audit` 的 capture/diff 指纹比对，承担「只有预期项变化」（T1）与「完全零差异」（T2 删除类）两类相对判据。它已是 24 页 × 逐元素 × 含伪元素的现成机制，本 spec 直接把它提升为 T1/T2 的正式门禁。
- **门禁（非行为测试）**：`astro check`、`prettier --check ./src`、`pnpm test:utils` 等既有单测与一次完整 `pnpm build`（含 LQIP/变体、快照、Pagefind）。

**不新增的缝隙**：不引入 CSS 快照框架、不为纯样式改动写单元测试（现有 `node --test` 系全部是带注入的纯逻辑测试，不适合本主题）、不给 `/domain/` 独立壳建立第二套测试基线（其断言并入缝隙 A 的一个页面组）。

**测量陷阱（写进脚本注释，防再次误判）**：无头浏览器走 overlay 滚动条，滚动条宽度类结论量不出来；自动化的点击会把目标滚进视口，滚动位移类断言必须避开；构建期随机与远端异步组件需冻结或排除；线上 Fastly HTML 缓存 600 秒且缓存键不含查询串。

**先例**：`scripts/fancybox-smoke.mjs`（同 base URL 约定、同「外部服务失败单列不计 FAIL」的处理）、`scripts/nice-books-smoke.mjs`、`scripts/upgrade-style-audit.mjs`（顺序无关比对与假阳性白名单）。

## Out of Scope

- 把 `/domain/` 纳入主站布局体系（ADR-0002 已否决，另案）。
- 断点体系重构（768 双断点合并、680/681 边界重划）。
- `@layer` 块的整体拆分与样式表重排。
- 网格类页面（相册、图片墙、项目、技能、友链、时间线）的卡片宽度与间距节奏统一。
- 真·降级搜索、服务端 Pagefind、任何引入 Node 运行时的方案。
