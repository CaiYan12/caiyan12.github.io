## What to build

把 Tailwind CSS 从 3.4.19 升到 4.3.4，并把接入方式从 PostCSS 插件改为官方的 Vite 插件。

这是一个接入方式的重写而不是版本升级，改完之后的产物行为与现在一致：站点现有的 Tailwind 配置文件继续生效（颜色、字体、阴影、圆角这些 token 一律照搬，不迁到 CSS-first 的主题块），站点的自定义色板照常可用，两套样式入口（主站与 Nice Books 独立壳）各自照常工作。

三处必须做对的地方：

1. **源码扫描范围必须包含 TypeScript 与 JavaScript。** Nice Books 的渲染构造器与交互脚本在 TS 模板字符串里拼装工具类；扫描范围漏掉 TypeScript 会**静默**丢失若干工具类——产物变小、零报错零警告，只有对照两版产物才发现。
2. **CSS 嵌套处理是必需项。** 主样式文件里有 8 处不带 `&` 符号的隐式嵌套（拉绳壁纸挂件的绳与衣身 SVG 子规则），没有嵌套处理器时这些规则是非法 CSS 会被整条丢弃。嵌套处理插件的**来源变了**：旧版本它是 Tailwind 包内附带的子路径，新版本的包不再导出该路径（构建直接报错），须改为显式依赖独立的嵌套处理包。
3. **厂商前缀处理保留。** 新版本内置的前缀处理器与既有 autoprefixer 的浏览器目标集不同（前者硬编码、不读 browserslist 配置；后者读 browserslist，而本仓库没有该配置故走其默认集）。实测本站自有规则在两条链下声明值零差异，但前缀集合不同——保留是为了维持既有产物的前缀行为不变。

- 229 页构建通过；dev / HMR / 源码扫描在 Vite 8.3.5（rolldown）上均正常。
- 「不能假绿」的核对方式：确认产物里确实有 Tailwind 生成的类，且 `.text-nb-*` / `.font-nb-*` 等自定义色板 utility 存在。
