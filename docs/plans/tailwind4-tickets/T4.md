## What to build

让仓库既有的样式指纹工具能承担**跨版本对比**的职责：把两个版本的构建产物分别采集成指纹，然后直接比出「哪些差异是看得见的」。

现状有两个缺口：

1. **地址归一化只认一种形式。** 采集期会把主机地址归一化，但目前只处理 `localhost:<端口>`，不处理 `127.0.0.1:<端口>`。两个版本用不同端口提供服务时，产物里每一个带绝对地址的声明（本站的手型光标资源、背景图）都会变成一条假差异——本次实测中，462 条差异里有 152 条属于这一类。
2. **差异输出不区分可见性。** 当前的比对结果按属性名罗列差异条目，读者必须自己判断每一条是否影响渲染。本次的实测里，462 条差异里有 308 条是边框颜色变化——而这些元素**边框宽度为零**，颜色根本不渲染，可见差异实际为零。一个不看渲染语义的人会被这 462 条淹没。

本工单补上这两点，使工具能直接回答「这一版相对上一版，访客看得见的变化是什么」。

## Acceptance criteria

- [ ] 地址归一化同时处理 `localhost:<端口>` 与 `127.0.0.1:<端口>` 两种形式；补上后，用不同端口采集同一份产物的两次结果，除归一化字段外逐项一致
- [ ] 差异输出按可见性分类：把「影响渲染的差异」与「不渲染的差异」分开列出，并在每类里给出条目数
- [ ] 判定「不渲染」至少覆盖：边框宽度为零时的边框颜色变化
- [ ] 采集与比对的既有用途（同一份产物连采两次必须一致）不受影响
- [ ] 页面清单沿用既有的分组（带壳真页面 13 页 + 扩展页面 10 页 = 23 页），不新增清单
- [ ] 用本仓库两个版本的产物实测：可见差异条目数为零；不可见差异按属性名归类后能逐条说明来源
- [ ] 工具的用法说明与既有命令文档一致
