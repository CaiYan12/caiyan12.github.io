## What to build

把这次迁移的承重结论写进仓库的文档，让下一个接手的维护者能接着往下走而不必重新推导。

有三处文档现在说的是「迁移前的事实」，迁移后不再成立或不完整：

1. **构建文档里关于 `@layer` 的那条承重结论**。它现在写的是「v3 的 `@layer` 是构建期指令，产物里根本不存在 `@layer`，冲突按『特异性 → 源顺序』判定」。必须改写成符合新版本的语义，并附上实测证据与被否掉的替代方案——特别是「只改层序声明不够」与「提高特异性一律无效」这两条，它们看起来很合理但都试过且无效，写下来能省下后来者的一次重复尝试。
2. **样式文档里关于构建链插件顺序的那条**，以及关于正文行内代码的那条——后者依赖旧的层语义推理方式，须补一句「涉及与排版插件的覆盖关系一律以实测计算值为准」。
3. **命令文档缺一条「样式 A/B 的判据纪律」**。本轮踩出的五个坑都值得写下来：预览服务器会把所有路径返回首页（导致指纹采集拿到假数据）、截图比对必须先定噪声底线（且要区分运行时随机与构建期随机两类来源）、判断规则是否生效要用真实 DOM 而不是手写样例、版本迁移改字号工具类的行高继承规则、以及样式测试可能对缩进有硬依赖。

同时要写一条 ADR 记录「保留 JavaScript 配置 + 移出所有层」这两个决定——它们难回退、有真实取舍（与官方推荐方向不同）、且令人意外。变更日志加一条新条目，README 待办区里 Tailwind 那一项从「进行中」改为已完成并写明关键机制与踩坑。
