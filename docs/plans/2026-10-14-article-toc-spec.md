## Problem Statement

文章页只有正文顶部一个 `<details class="post-toc">`。长文里这不够用：以 `20261011101832`（《看懂 AI 写的网站》第五章）为例，实测它有 **62 个标题**（15 个 h2 + 47 个 h3），正文滚动高度 **31642px**。读者翻到下半篇想跳章节时，必须先把页面滚回顶部、再在目录里找——而目录本身在滚动中早已离开视口。

侧栏此时是闲置的：它的最下方只有一个「文集目录」小部件（该文属于文集时才有），且它已经具备粘性跟随能力（滚过自然位置后钉在视口顶 10px 处）。侧栏之上有大量空白可用。

阻塞点在于「目前读到哪里」这件事站内从未计算过：既有的所有「当前态」都是**构建期**判定的（文集目录的当前章就是把 URL 里的 slug 和成员 id 直接比出来），而「当前正在阅读的章节」只能**运行时**算。

## Solution

在侧栏「文集目录」之下新增一个「文章目录」小部件，与它**共用同一个粘性容器**，滚过自然位置后整体钉住不再上移；其条目**不是**构建期一次算好的，而是运行时采集正文标题树生成，并让**激活态跟随当前阅读位置**。

正文顶部的 `.post-toc` **保留不动**：本站 `#sidebar` 在 ≤768px 是 `display:none !important`，移动端根本没有侧栏，顶部那份是那里唯一的目录入口。两处由此成为**同一份内容的两种放置**（同源同序），只容许在容纳方式与激活态上不同——这条已写进 `GLOSSARY.md` 的「文章目录」词条，成为「改动一处须同步另一处」的依据。

## User Stories

1. 作为读者，我希望在文章页侧栏看到当前文章的目录，这样我翻到下半篇时不必先滚回顶部。
2. 作为读者，我希望侧栏目录滚过自然位置后钉住不再上移，这样我在长文中滑动时它始终可用。
3. 作为读者，我希望侧栏目录的条目跟随我的阅读位置高亮，这样我一眼知道自己读到哪一节。
4. 作为读者，我希望长文里目录条目能在其容器内滚动，这样 60 多条目录不会把页面撑长。
5. 作为读者，我希望当前激活的条目自动滚进目录容器的可见范围，这样我不必在一个看不见当前项的长列表里摸索。
6. 作为读者，我希望目录条目是单行截断的，这样长短不一的标题不会让列表高矮参差。
7. 作为读者，我希望把鼠标悬停在被截断的条目上能看到完整标题，这样截断不造成信息丢失。
8. 作为读者，我希望目录条目的跳转是精确到小节的（h2 与 h3 都列出），这样我能直接跳到「5.3 Package」而不是只能跳到「5. Node.js」。
9. 作为读者，我希望点击目录条目能可靠地跳到目标小节，且不被顶部元素遮挡。
10. 作为读者，我希望在页面刚刚载入、还没读到第一节时，目录里没有任何条目被点亮，这样我不会误以为自己在第一节。
11. 作为读者，我希望读到文章末尾时目录指向最后一节，这样高亮不会停在倒数第二三节。
12. 作为键盘使用者，我希望目录条目是可聚焦链接并按 DOM 顺序排列，这样我能用 Tab 遍历并用 Enter 跳转。
13. 作为读屏使用者，我希望侧栏目录与顶部目录的导航地标有可区分的名称，这样我能分辨这两个导航区域。
14. 作为读屏使用者，我希望被高亮的条目以「当前文档内的位置」语义播报，而不是被误读成「另一个页面」。
15. 作为使用窄屏（≤768px）的读者，我希望顶部目录继续可用，这样我在没有侧栏的设备上仍有目录入口。
16. 作为使用矮视口（如横屏笔记本或 360px 高窗口）的读者，我希望侧栏目录不被切掉、其底部仍可滚到，这样矮窗口下它依然完整可用。
17. 作为读者，我希望侧栏同时出现「文集目录」与「文章目录」时能一眼分辨，这样我不会把「这本书有哪些章」和「这一章有哪些节」看混。
18. 作为读者，我希望访问一篇不属于任何文集的文章时，侧栏只有文章目录、不出现空的文集目录，这样界面不出现空洞。
19. 作为读者，我希望访问一篇零标题的文章时，侧栏不出现空的目录盒子，这样界面不出现孤立边框。
20. 作为读者，我希望从一篇文章通过站内链接切到另一篇时，侧栏目录能立即换成新文章的目录，这样无刷新的页面切换不会留下旧目录。
21. 作为读者，我希望从长文切走后滚动位置归零、目录高亮不残留上一页的状态，这样切页不会造成位置错觉。
22. 作为维护者，我希望顶部与侧栏两处目录的门槛一致（有标题就出现），这样不会出现「顶部有目录、侧栏没有」这种看起来像 bug 的状态。
23. 作为维护者，我希望侧栏目录的激活态判定是一条可离线单测的纯函数，这样这条新增的计算规则不依赖浏览器即可回归。
24. 作为维护者，我希望侧栏粘性栈的几何由已有机型的冒烟脚本守住，这样矮视口溢出一类的回归能被自动发现。
25. 作为维护者，我希望新增样式的色值、字号与线型全部取自既有 token 与既有规则，这样不引入新的设计语言。
26. 作为维护者，我希望这件事的取舍（为何两个小部件必须共用粘性容器、为何需要弹性高度）记在 ADR 里，这样将来的人不会把它当冗余结构删掉。
27. 作为维护者，我希望两条术语（文章目录 / 文集目录）在词汇表里互为对照，这样命名不再重名混淆。

## Implementation Decisions

### 数据与运行时

1. **标题树运行时采集，不新增数据管道。** `headings` 只存在于文章页的 `render(post)` 产物中，而侧栏由被 28 个页面共用的布局渲染，拿不到它。采集方式为运行时查询正文容器内的 `h2/h3/h4`，**不新增任何页面级 prop**。
2. **采集口径与顶部目录同源**：depth 2–4（顶部组件当前的过滤区间）。站内现存的标题层级实测只有 h2 与 h3（最长一文为 15 h2 + 47 h3），h4 出现在另一篇（9 个）；沿用同一区间即可，不额外加规则。
3. **必须在 swup 切页后重新采集。** 实测从一文切到另一文时，标题数由 61 变为 46、滚动位置归零、`widgetSeries` 仍在。模块级监听器只绑一次（`bound` 守卫），每次切页重跑的是「重新采集 + 重置激活态」。
4. **运行时模块接入既有装配表**：新增一个 runtime 模块，并在既有装配表的 `swap` 序号序列后追加下一个未用序号。仅当存在真实依赖顺序需要时才挑号，不重排既有编号（装配表注释已声明「序号与表序不同是历史事实，不是笔误」）。
5. **零标题时的降级在运行时做**：运行时采集到 0 条时，移除新元件并把粘性职责交回文集目录自身（它原本就是粘性元素），避免留下空盒子与多余包裹层。

### 结构

6. **新增一个组合组件承担粘性容器**，包住「文集目录 + 文章目录」两个小部件，而不是在通用循环里插特例。理由：把「哪两个小部件同粘」收进一个文件，通用侧栏只多一行调用；将来其中之一消失时只动这一处。
7. **两个小部件共用一个粘性容器是硬要求，不是选择。** 实测同一侧栏内两个各自 `sticky`、各钉在相同视口偏移的兄弟元素，滚动后**互相压住 87.9px**（前者 10–230，后者 142.1–342.1），后者最终整块盖住前者。因此不给第二个小部件写死偏移——文集目录高度随成员数变化，写死必然错位。
8. **粘性容器的容纳由弹性高度解决。** 实测 360px 高视口下，固定高度方案的外壳高 424px、超出视口，且内部列表滚到底时最后一条仍在视口之外；改为「视口高减去上下留白」的弹性高度并给容器链上每一层补 `min-height: 0` 后，900/720/500/360 四档全部装得下，且「滚到底最后一条可见」在 360px 下由否转为是。
9. **`min-height: 0` 是弹性布局的必要条件**，不是引入新设计语言；计入「新样式」时按此口径理解。

### 呈现

10. **列表全量列出，容器内滚**，`max-height` 沿用顶部目录既有的 `45vh` 口径。
11. **条目单行截断**，照抄既有 `#hotlog li a` 范式；`<a>` 一律带 `title` 属性给全文（与文集目录现有写法一致）。**不**按「是否被截断」条件性添加：那需要运行时量宽，而该判断在字体加载前后会漂移。
12. **缩进沿用顶部目录的每级 18px 口径**（实测侧栏字号为 12px，61 条目录在 18px 缩进下全部单行、零换行、零横向溢出）。
13. **标题栏只放图标 + 「文章目录」**，不显示节数：255px 宽的标题栏在 14px 字号下已接近占满，且与文集目录保持同族结构（图标 + 标题 + 可选动作槽）。
14. **图标取 `fa-list-ul`**，与顶部目录同图标（语义上「同一份内容」），并与文集目录的 `fa-list-ol` 形成「无序的节 vs 有序的章」的区分。
15. **激活态样式照抄文集目录的两条既有规则**（字重 700 + 无障碍绿），不新增光标规则——链接的默认手型由既有侧栏规则提供，站内有一条「手型负扫」判据不得裸写 `pointer`。
16. **导航地标命名可区分**：新元件的 `aria-label` 用「侧栏文章目录」，**不改动**已通过验收的顶部组件（其同名地标保留，避免波及既有判据）。
17. **激活项语义用「文档内的当前位置」**，而**不是**「当前页」——后者会误导读屏这是另一个页面。文集目录用「当前页」是对的（它指向另一个页面），此处不同。

### 激活态规则

18. **判定规则：最后一个「顶部已越过判定线」的标题为当前项**；判定线取与粘性钳位线相同的 10px。理由：粘性元素钉在视口顶 10px 处，读者的视觉顶线即 10px，同一数值可让激活项与视线一致；取 0 会提前 10px 跳变，取「上三分之一」会明显滞后（720px 视口下约滞后 240px）。
19. **页底兜底**：滚到文档底部时强制激活最后一条。实测在最长的一篇上「按位置算」与「强制最后一条」结果相同（滚到底时 61 条全部越线），因此它在当前内容上不产生差异，**保留它是给「尾部标题距页底很近、按位置永远到不了最后一条」的文章兜底**，不是为了修当前这篇。判据形态：`scrollY + innerHeight >= scrollHeight - 1`。
20. **首个标题越过判定线之前，不激活任何条目。** 实测初载与 swup 切页后首个标题都在视口下方约 1100px 处（文章开头的头图与元信息区较长），此时「没有正在阅读的章节」是真实状态。这是与 `.current` 成对存在的有意状态（词汇表的「当前页态」约定：算了就必须有人画），不是未定义行为。
21. **激活项变化时让它滚进容器可见范围**，用直接设置容器 `scrollTop` 的方式，**不用** `scrollIntoView`——后者会向上冒泡影响所有可滚动祖先，包括页面本身；在这个已有粘性侧栏、且被几何判据严密监控的站点上，这类越界滚动是难查的抖动源。算法就两行：比较条目的上下边界与容器视口。
22. **点击条目后不做「锁定激活态」**：判定完全交给滚动位置。实测站内 `scroll-behavior` 无任何声明（全站零命中），锚点跳转是瞬时的，不存在可感知的「中途扫过」窗口；加锁定反而引入需要超时清理的状态。
23. **顶部目录不加激活态**：读者看到它时通常尚未开始往下读，且它可折叠、折叠时高亮不可见。给它加等于把同一份运行时计算服务两处，收益低耦合高。
24. **锚点跳转不需要额外偏移**：实测导航栏是文档流内的相对定位（滚动后移出视口）、标题 `scroll-margin-top` 为 0、锚点点击后目标顶端落在 0.2px，顶部无任何遮挡，故偏移取 0。

### 门槛与边界

25. **出现门槛与顶部目录完全一致：有标题即出现**。选项曾考虑设阈值或仅限文集成员，均否掉——门槛不一致会造出「同一篇顶部有目录、侧栏没有」这种读者会当 bug 的状态。
26. **移动端不做侧栏目录**，与文集目录同命。这是既有裁决的延续（移动端目录入口由正文顶部承担），若要做移动端形态，那是另一个元件，应单独立项。

## T5 增补（#102，2026-10-14）：激活项居中与到达动画

grilling 六问全取推荐（2026-10-14），对上文激活态规则三处对照：

- **决定 21 保留**：目录自动滚动仍以直接设置容器 `scrollTop` 实现，**不用** `scrollIntoView`——rAF 自绘分帧设值继承同一约束，不冒泡页面滚动。
- **决定 21 的算法推翻**：「越界才拖回边缘」改为**居中钳制**——激活项中线对齐容器中点，列表首尾不足半屏时钳制到 `[0, scrollHeight − clientHeight]`，第一章不拖出顶部空白、末章不拖出底部空白。已知后果（裁决接受）：亮行指向「正在读的那节」，与视口顶判定线 10px 视觉脱开，与主流阅读器一致。
- **决定 22 部分推翻**：「锚点跳转瞬时、不存在可感知中途扫过」的前提不再成立——激活到达现在有约 200ms 的 rAF 自绘动画（新激活取消旧动画、从当前进度追新目标，不排队不积压；连续变化约 100ms 防抖后才启动；`prefers-reduced-motion` 下全部瞬时，照 theme-script 的站内回退惯例）。「点击条目后不做锁定激活态」**保留**：判定仍完全交给滚动位置，锚点点击照旧瞬时跳页，目录随后以动画追上。
- **新增**：手动让位——用户滚动目录后 3s 内激活变化只改高亮不滚容器，静默 3s 后恢复自动居中。「用户滚动」以输入事件源识别（wheel / pointerdown / keydown），不监听 scroll 做程序写值配对——后者对事件合并/派发时序脆弱（首版实测：冒烟前置段程序化写容器 scrollTop 每次都武装让位窗口，间歇性吞掉后续 reveal，触发源两轮未定位）；**点击条目链接清除让位窗**（2026-10-15 站长实测推翻首版「可接受」裁定并补充「先滚动后点击也要回正」：点击是导航意图而非浏览目录，跳转后激活项应照常居中——首版 pointerdown 一律武装让位，「直接点链接」与「先滚目录再点链接」两条路径的跳转后居中都被吞掉 3s，亮行停在原处；命中链接的 pointerdown 清让位窗，滚动条拖拽/空白处仍武装）。高亮切换只过渡颜色（180ms ease-out，照侧栏 actions 槽 `.weather-widget__refresh` 先例），字重 700 无中间值，跳变保留。
- 目标 scrollTop 计算（居中 + 钳制）抽为纯函数 `pickTocRevealScrollTop`，与 `pickActiveIndex` 同落缝 B 单测。

27. **超长目录不做特殊处理**（不降级为只列 h2、不默认折叠 h3）。实测全站 573 条标题中仅 57 条超过 25 字（最长 88 字），容器内滚已解决容纳问题；而只列 h2 会丢掉最长那篇里 47 个 h3 的跳转粒度，恰是它长的原因。

## 测试决策

### 什么是好测试（本站既有口径）

只断言**外部行为**：DOM 的存在与否、链接指向、计算值与几何、键盘结果、ARIA 属性。绝不锁 CSS 源文本、类名字符串或行号。涉及动画或几何的判据，**相位一律由状态定义，不用固定等待**（等动画落定、等计算值到达阈值、或逐帧采样要求每帧满足不变量）。相对判据（"只有预期项变化"）由既有的样式指纹工具承担。

### 测试缝（两条，均为既有缝，不新开入口）

本站已把「缝」文档化为两条：

| 缝              | 形态                     | 台子 / 入口                                                                                             | 进 CI                                           |
| --------------- | ------------------------ | ------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| **缝 B** 纯函数 | `src/utils/**/*.test.ts` | 既有 `pnpm test:utils`（其 glob 已覆盖 `src/utils/runtime/`，与既有 `runtime/quote-band.test.ts` 同处） | 是（`test:utils` 在 `build` 链头，CI 跑 build） |
| **缝 A** 冒烟   | 真构建产物 + 真浏览器    | 既有 `scripts/lib/smoke-harness.mjs` 的 `makeHarness(...)`                                              | 否，`smoke:*` 手工跑                            |

### 落在缝 B 的纯函数

26. **新增一个 runtime 侧的纯函数模块**，把激活态判定从 DOM 中剥离出来：输入是标题的文档坐标数组、当前滚动位置、视口高、文档总高、判定线阈值，输出激活索引（`-1` 表示不激活）。DOM 采集与事件监听留在同模块的非纯部分，照既有 `runtime/quote-band.ts` 的分工（纯函数导出供单测，副作用留在 init 里）。
27. **单测覆盖**：首标题越线前返回 -1；越过第一条返回 0；越过第 k 条返回 k；滚动位置落在两条之间返回前一条；滚到页底返回最后一条（含「按位置已满足」与「按位置未满足、靠兜底满足」两种输入）；空标题数组返回 -1；单条标题的两种状态。
28. **先验依据（prior art）**：`src/utils/runtime/quote-band.test.ts` 是同一形状——把既有内联逻辑抽成纯函数后补单测，走同一个 `test:utils` 入口。

### 落在缝 A 的冒烟

29. **扩写既有 `scripts/series-smoke.mjs`**，而不是新开一个脚本。理由：两个小部件从此共用同一个粘性容器，粘性几何在物理上无法分开验证；拆成两个脚本会让同一段几何被两处断言、改一处要同步两处。该脚本已有现成的粘性台子（**360px 高的专用视口**、自然位置推算、底边重合换算），可直接复用。
30. **新增判据方向**（具体条数与命名在 tickets 阶段定，此处只定方向）：
    - 侧栏出现文章目录，且其条目数与非空集合与顶部目录**同源**（同一篇文章两处的 href 序列一致）。
    - 侧栏**不**出现空目录盒子（零标题文章）。
    - 长文页条目带 `title` 属性。
    - 条目为单行（`getClientRects().length === 1`）而非换行。
    - 粘性容器在滚过自然位置后钉住，且**两个小部件不重叠**（用既有几何换算方式量）。
    - **矮视口下容器不溢出视口、且内部列表滚到底时最后一条仍在视口内**（360px 视口）。
    - 高亮态**真的被画出来**：滚动到某个已知小节后，对应条目的计算样式与其他条目不同（断言计算值差异，不锁具体颜色字符串）。
    - 首标题越线前**没有任何条目被点亮**。
    - 键盘可聚焦：条目为链接且按 DOM 顺序。
    - 侧栏与顶部两处地标的可访问名称**不相同**。
31. **该脚本尾部写死判据总数并在不符时退出码 2**（注释称 #49 不变量）。扩写判据必须同步上调该基线数，并在脚本头注释里注明理由——这正是该不变量自己要求的动作（「改判据必须同步 EXPECTED_CHECKS，并说明理由」）。
32. **不把判据塞进既有 `smoke:ui`**：那是主站 UI 判据集合，其条数被当基线引用过，往里加会让该基线漂走。

### 红证据（沿用本站「每票都要有红证据」的测试文化，偏好变异式自证）

33. 纯函数侧：每条规则各造一条反例输入，证明规则真的在起作用（尤其「首标题前返回 -1」与「页底兜底」两条，它们的正例在真实内容上可能恰好重合）。
34. 冒烟侧：至少做一次变异自证——例如临时把激活态判定的判定线改成明显错误的值、或临时让两个小部件各自独立粘性，证明相应判据会红。

## Further Notes

### 本轮质询中被实测推翻的三处初始判断（留档以免重犯）

1. **缩进**：曾建议把侧栏缩进从每级 18px 减到 12px，理由是「两级缩进后文字区太窄」。实测侧栏字号为 12px（顶部是 14px），18px 缩进下 61 条目录**全部单行、零换行、零横向溢出**——建议作废，采用 18px。
2. **超长目录**：曾建议「不必特殊处理，内滚已解决容纳」。实测全站 573 条标题中 57 条超过 25 字（最长 88 字），另一篇 42 条中有 14 条折到 3 行——判断依据不完整。**是归纳过宽，不是测量错误**（最长那篇的标题确实都短）。改用既有的单行截断范式。
3. **粘性容器**：曾判定「单粘性容器在矮视口成立」，依据是 720/900px 视口的实测。补测 360px 后发现**外壳高 424px、超出视口**，必须补弹性高度归一。

### 探针记录的作废项

两次一次性探针因构造缺陷被主动作废、未采信任何结论：① 用 `getBoundingClientRect().height` 去数行内元素的行数（行内元素的 rect 高度是字体度量，不是行数，应改用 `getClientRects().length`）；② 弹性布局的最小复现漏掉了中间层容器，导致子项不收缩、读数无效。**留档理由**：这两类错误都会让读数「看起来是数据」，但方向恰好相反（前者偏向假绿，后者偏向假红）。

### 两个已知的「看起来像缺陷、其实是有意的」

- **页底兜底在最长的一篇上不产生差异**（滚到底时全部条目已越线）。它是给尾部标题贴近页底的文章准备的，不要因为「当前没效果」而删掉。
- **首批进入页面的若干屏内没有任何条目被点亮**。这是有意的「尚未开始阅读任何一节」状态，不是采集失败。
