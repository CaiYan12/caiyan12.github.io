# 样式约定

> 本仓库的 CSS 约定：层级与特异性、token 来源、组件类名复用、已转正偏离项。**改任何样式前读这份**——里面的规则比任何通用建议都具体。

（本文由 `AGENTS.md` 的「样式约定」一节迁出；内容逐字保留。）

## 样式

- `src/layouts/Layout.astro` 全站引入 `src/styles/markdown-extended.css`；所有经 `MainGridLayout` 渲染的主站正文页共享 GitHub 卡片、提示块、spoiler、图片网格、Mermaid 等扩展样式，选择器统一收敛在 `.post-context` 下。独立的 `/ai-news/` React 页面不使用该 Layout，保持隔离。
- GitHub 卡片的结构由 `remark-extended.mjs` 生成：`.github-card-link` 使用两列 grid，`.github-card-avatar` 为装饰性图片（`alt=""` + `aria-hidden="true"`），`.github-card-body` 必须 `min-width: 0`，仓库名允许任意位置换行，避免长仓库名撑破正文。
- 表格通用规则位于 `global.css`：`.prose table`/`.prose th`/`.prose td` 提供 `#c4c4c4` 边框、`vertical-align: middle` 和表头底色；`.post-context table` 统一 `width: 100%`，`.table-scroll` 负责过宽表格的局部横向滚动。新增表格不要在文章内另写宽度或滚动容器样式。
- **根字号基线：本站根字号 = 浏览器默认（`html{font-size:100%}`，实测 16px）**。主题尺寸全靠 `px` 书写，`rem` 只出现在 Tailwind 的间距与字号工具类里——所以"把根字号改成 13px 以贴近原版"这类想法**已明确否决**：那会让全部 rem 工具类集体缩放，等同全站重排。源码里曾长期存在一条从未生效的 `html{font-size:13px}`（写在 `@layer base` 内，被更靠后源顺序的同特异性 `100%` 压掉），2026-09-22 已删除；不要按它的存在推断任何度量。
- `src/styles/global.css`：Tailwind 指令 + 大量自定义 class（`.post-list`、`.tw`、`.widget`、`.pagenavi` 等，命名直接对应原主题 CSS），**视觉还原以 custom class 为主、utility 为辅**
- **正文段落首行缩进（2026-10-10 新增）**：规则 `.post-body p { text-indent: 2em }`，写在 `global.css` 里 `.post-context p` 紧邻处。用 `em` 不用 `px`——`.post-context` 的字号由字号滑块写内联 px（12–24），`px` 不跟手（基准字号实测 13px，文章页默认缩进 26px）。**挂点 `.post-body` 只加在两处真的渲染 markdown 正文的容器上**：文章页（`[...slug].astro`）与 `/about/`（`about.astro`）。`/tag/xxx/`、`/category/xxx/`、`/series/xxx/` 的统计行共用 `.post-context` 但**没有这个类**，写成 `.post-context p` 会把它们一起缩进（`.post-context` 在 TaxonomyListing / SeriesListing 里不带 `.prose`，是同一处边界的另一半）。**八条例外**：图片段 `p:has(> img:only-child)`（`.post-context img` 是行内图，缩进把图右移 2em 并溢出容器）、`.admonition-title` / `.markdown-alert-title`、`blockquote p`（含嵌套）、`svg p`、`td/th p`、`li p`、`.post-last-updated` / `.post-series`、`/about/` 的居中装饰标题 `.paper-hero-title` / `.paper-hero-sub`；另有两处**就地写进既有规则**而不另起选择器：右对齐的日期落款并入 `markdown-extended.css` 的 `.letter-paper-body p:last-child`（那条本来就是 `text-align: right`）、逐字 span 并入 `.paper-hand-char`。**最容易漏的两条**：`svg p`（mermaid 节点文字是 SVG `foreignObject` 里的 `<p>`，全站三百余个，抽一两篇抽查根本看不见）、`.paper-hand-char`（见下一条陷阱）。原版主题零 `text-indent`，本条属 ADR 0004 的已转正偏离，**审计不得当漂移修回原版**。
- **陷阱：`text-indent` 是**可继承**属性，会打进 `display: inline-block` 子元素并各自生效。** 稿纸的逐字符微随机把每个字包成 `inline-block`（= 独立块容器），段落那条缩进因此被每一个字各缩一次——实测稿纸正文各段高度翻到三倍（64→192 / 128→352 / 192→544px）、面板高度 2691→4771px，而字符矩形数与网格相位变量一个没变，极易误判成"CDN 字体换了"。故 `.paper-hand-char` 必须显式 `text-indent: 0`，缩进只留在段落首行。**复核口径是"段落内所有 `inline-block` 后代的 `text-indent` 都为 0"这条扫描**，不是看段落自身的缩进值（段落值全程正确）；**判定手段是同一浏览器会话内摘/挂挂点类做 A/B**，跨会话重开浏览器会把 CDN 字体的加载时序差误读成缩进造成的。改这条规则必须按「段落形态」穷举扫描全部文章页复核，不能按篇抽查。
- 正文行内代码（2026-09-19 定）：字号 `max(12px, 0.9em)` 随所在文字等比缩放，**各级标题共用同一倍率**，字体走 `var(--font-mono)`；规则写在 `global.css` 的 `.post-context code` 附近，选择器必须是 `.post-context :not(pre) > code`（0,1,2 才压得住 legacy 的 `.post-context code`，同时避开 Expressive Code 的 `PRE.wrap > CODE`，代码块仍归它自己的 14px mono）。**必须同时关掉 `@tailwindcss/typography` 给行内 code 前后注入的反引号伪元素**（`.prose :not(pre) > code::before/::after { content: none }`）——该插件默认把行内代码画成 markdown 源码模样，与本站已有的边框+底色芯片叠加后被访客读成「反引号漏渲染」；选择器不排除 `pre code` 会连带抹掉 Expressive Code 自己的 `code::before` diff 标记。另注意 `.prose code { font-size:13px; font-family:var(--font-mono) }` **在桌面一直是生效的**（它位于源码 `@layer components` 块内；Tailwind v3 的 `@layer` 是构建期指令，产物里没有级联层，所以不存在"被层压住"的机制——旧记录曾把它误写成"关在 `@media (max-width:680px)` 内、桌面永不生效"，两条都是错的：该文件里它之前的两个 media 块都已闭合）。它之所以盖不住行内代码：覆盖关系由**特异性**决定，`.post-context :not(pre) > code` 是 `(0,1,2)` > `.prose code` 的 `(0,1,1)`（此前写成"靠源顺序"也不准确）。legacy `.post-context code { font:12px Arial,"Microsoft JhengHei" }` 因此不是行内代码的兜底来源，改字号/字体要改上面那条新规则而不是它。**折行**：`.post-context { word-break: break-all }`（原主题为中文排版所加，global.css ~3042 行）会被行内代码继承，长命令在任意字符处断——实测把 `setup-matt-pocock-skills` 切到第二行只剩 1 个字母（两行宽 166/7）；故同一条 `:not(pre) > code` 规则里必须带 `word-break: normal` + `overflow-wrap: break-word`，让断点回到连字符/斜杠边界（同处实测 130/43）且超长 token 仍不撑破版面。中文正文的 `break-all` 保持原样，只有行内代码退出
- 返回顶部按钮与灯箱（2026-09-20 定）：`.backtop` 以 `left:50%; margin-left:-614px` 相对视口居中锚定。Fancybox 打开时给 `html` 加 `with-fancybox`、给 `body` 加 `hide-scrollbar{overflow:hidden}`，把本站固定 10px 的根滚动条（`::-webkit-scrollbar{width:10px}`）收掉，fixed 元素的包含块因此从 1430 变 1440 → 按钮右移半格；正文列有 Fancybox 自身的 padding 补偿并不动，差值就是访客看到的「开灯箱后按钮偏移」。修法是 `global.css` 里 `html.with-fancybox .backtop{margin-left:-619px}`（紧跟 `.backtop:hover` 之前，实测 1440 视口下位移从 +4.9px 收敛到 -0.1px）。**勿改成 `html{scrollbar-gutter:stable}`**——实测那样灯箱容器只盖到 1430，右缘会露出一条未变暗的页面；也不要用「开灯箱就藏掉按钮」绕过去（`.backtop` 的 display 由 JS 内联样式切换，得写 `!important` 且会闪）。量测这条改动只能用真实浏览器，且要避开两个**测量陷阱**：其一，headless Chromium 走 overlay 滚动条（`innerWidth === clientWidth`），滚动条宽度类问题完全量不出来，必须 `chromium.launch({ headless:false, channel:"msedge" })`；其二，Playwright 的 `locator.click()` 会先把目标滚进视口，于是量到 12～3244px 不等的 `scrollTop` 变化 —— 那是自动化工具在滚页面，不是站点缺陷（曾被误判成「开灯箱后页面跳位」，实测图已在视口内时用 `page.mouse.click(x,y)` 或合成 `el.click()`，Δ 均为 0）。
- **层叠关系表（2026-09-22 票 22 立；下列数值全部是真实浏览器读到的**计算值`z-index`**，不是源文本）**：`.skip-link`(1000000) > `#myhkplayer`(900000，`Layout.astro` 内联 `!important`) > `.site-toast`(100100) > `.colorful_loading_frame`(99999) > `.click-word`(9999) > `.post-navigation a`(1000) > `#nav li ul` 与 `.qrcode-pop`(999)。**谁必须位于谁之上是契约，改任一值前先回到这张表核对**；其余约 50 处散值（`global.css` 40 / `books.css` 8 / vendored 与独立壳若干）为既定关系，本轮有意不动。
    - **陷阱一：`z-index` 是 32 位有符号整数。** 写 `10000000000`、`10000000001` 这类超界值不会报错，浏览器把它们**静默钳到 `2147483647`** —— 于是两条「看起来差 1」的规则算成**同一个数**，谁盖谁退化为绘制顺序侥幸。票 22 修的就是这一对（跳过链接与常驻播放器），现已各自落回可表示区间并留 10 万余量。判据必须读计算值：本仓库的冒烟用 `getComputedStyle`，源文本永远看不出这件事。
    - **陷阱二：Fancybox 灯箱是模态 `<dialog>`，走顶层层（top layer）**，`.fancybox__container` 的计算 `z-index` 是 `auto`。**不要拿 z-index 数值去和它比大小**——顶层层结构上压过一切非顶层内容，比数值会得出「特效字 9999 高于灯箱」的反向结论。实测（票 22 命中测试）：灯箱打开时在容器界面内放特效字与提示做 `elementFromPoint`，命中结果都落在灯箱一侧。
- **源顺序陷阱：vendored `font-awesome.css` 被拼在 `global.css` 之后**（`Layout.astro` 的 import 顺序决定；实测产物 `dist/_astro/MainGridLayout.*.css` 里 `.fa{}`@169652 > `.weather-widget-body{}`@126666）。于是 `.fa{display:inline-block; font-size:inherit}` 与普通类同为 (0,1,0) 时**压过后者**（源顺序在后者胜出）：给带 `.fa` 的元素写 `.x{font-size:48px}` 会被 `.fa` 的 `font-size:inherit` 盖掉、`display:none` 也会被 `.fa` 的 `display:inline-block` 顶回来。**改这类元素一律用复合选择器 `.x.fa`（0,2,0）提特异性**，别用普通类。2026-10-27 天气胶囊的加载转圈因此从 FA4 字形改成自绘 SVG（顺带甩掉这道依赖，也不再受字体 ascent/descent 撑高行盒的影响）。
- 分页控件（`src/components/layout/Pagination.astro` / `.pagenavi`）统一使用无圆角 40×40 方块；正常态为品牌色边框，当前/禁用态为深灰边框，跳转输入框为 120×40 且隐藏数字微调箭头；导航符号为 `<<`、`<`、`>`、`>>`、`→`，移动端仅保留首、前、当前、后、末五项。
- 文章卡底那条彩色分隔线按 `.post-list:nth-child(N)::after` **正向枚举**（`src/styles/global.css`，色值 2…9 与 10…12 位取自 `docs/reference/colorful-original.css`，第 8 位有意改用品牌绿），**未命中的序号静默落回基色品牌绿**——枚举到的深度必须盖过「每页条数 + 首卡之前的兄弟节点数」。首卡的 `nth-child` 序号**每类列表页都不同**（2026-09-30 实读线上计算值）：首页 3（`#content` 首卡前有 2 个兄弟）、`/hot/` 与单分类/单标签/月归档 2、`/page/2/` 1，所以每页 10 条时最深落到 `nth-child(12)`。把 `postsPerPage` 再往上调时必须同步往下枚举，否则第 8 张之后全是绿条（当时就是先红了才补的）；判据要写在**真实列表页**上并按页型取 max，别只看首页。**末页条数不足时分页重新浮到侧栏中段**（现 13 篇公开文 → 末页 3 张），站长 2026-09-30 明确认可，勿当缺陷重开。

    - **三个静默失效的坑，都是实测抓出来的**：① `.is-armed:not(.is-reroll)`（容器那一段只在首次播，换句时卡片已在屏幕上，再淡出一次只会闪背景）是 **(0,3,0)**，所以 reduced-motion 里那条覆盖**必须把 `:not(.is-reroll)` 一起抄过去**，只写 `.is-armed` 是 (0,2,0) 会被压掉、位移悄悄回潮——这条就是当场翻红发现的。② `clip-path` 在 `none` 与 `inset()` 之间是**离散**插值：中文行原本在退场第 30ms 就整行消失（擦走根本没跑），基态必须显式写 `clip-path: inset(0 0 0 0)` 让两端都是 inset；而 reduced-motion 下撤掉 clip-path 之后**必须把 transition 一起改成 opacity**，否则又变成瞬间删除。③ **`clip-path` 切的是盒子，不是墨迹**：中文行原本 `width:100%`（720px）而居中文字只有 227px，左右各 246px 空白，于是 34% 的行程在切空白——文字读起来是在动画 1/3 处蹦出来、2/3 处消失，站长实眼判定为"没有动画"。改 `width: fit-content; margin: 0 auto; max-width: 100%` 让盒子贴住墨迹（实测盒宽与墨迹宽**逐像素相等**）才成立；`smoke:ui` 有一条「桌面视口下中文行的盒子贴住墨迹」的判据守着，防止将来谁把它改回满宽又"看起来没动画"。**它必须在桌面视口量、且必须排除换行的那些行**：换行时 fit-content 的盒子被可用宽度夹住、本来就不贴墨迹，那是正常几何不是缺陷（实测同一批 42 条：1440 下 0 条换行、差值全为 0.0；390 下 7 条换行、最大差 29.8）
