# 0017：Nice Books 独立维护与 Pages 发布

2026-11-12。归属与迁移边界已由站长在 `/grill-with-docs` 两轮对齐中确认，随后授权 `/implement-spec` 本地实施。当前博客仍持有 Nice Books 实现，独立项目在 `D:\pages\nice-books` 构建，目标仓库为 `CaiYan12/nice-books`，通过 GitHub Pages 发布到 `/nice-books/`，由新项目独立维护源码、资源、配置、测试、构建与发布。

## 背景

站长希望 Nice Books 后续单独维护。现有实现集中在 `src/nice-books/` 与 `src/pages/books/`，但仍使用博客的站点配置、Tailwind 配置、Swup 装配、减少动效工具及测试基础设施。这些依赖需要在迁移时获得明确归属。

## 已确认决定

- 首版完整迁移现有视觉、全部书目、书籍 ID、随机推荐、书库搜索筛选、双视图、3D 书封与动效。沿用现有技术栈和 `books.ts` 维护方式，以当前产品表现作为迁移验收基准。
- 独立项目保留现有 Swup 无刷新切页、后退恢复与页眉高亮，并在自身配置内提供页面初始化、离页动画及请求清理所需的生命周期。
- 无效地址使用 Nice Books 自己的 404 页面，复用现有页眉、页脚与样式，提供简短提示、“今日好书”和“书库”入口。
- 新项目独立持有所需资源、样式配置、工具、字体依赖、图标与验收脚本，独立构建和发布。博客保留导航入口、新的 `/nice-books/` sitemap 入口与过渡期旧地址承接。
- `/books/`、`/books/archive/`、`/books/<id>/` 在过渡期分别跳转至 `/nice-books/` 下的对应页面，并保留查询参数与锚点。站长将在后续博客遗留代码与文档清理任务中安排旧地址退役。
- 新仓库采用迁移时的完整快照起步，后续修改从迁移提交开始记录，原有修改历史继续在博客仓库查阅。
- 本地独立项目位置确定为 `D:\pages\nice-books`，由该目录独立持有项目文件和 Git 仓库。
- 沿用“Nice Books · 每日好书”、现有文案与头像。新项目持有自己的图标文件，“返回主站”指向 `https://caiyan12.github.io/`。
- 先完成独立项目本地验证，再由站长建立仓库并配置 Pages。独立站线上访问及核心交互验收通过后，切换博客入口、启用旧地址承接并移除博客中的原实现。
- 本次切换时完成归属清理，移除博客中的 Nice Books 功能源码、专用构建及测试依赖，同步当前维护文档。历史记录保留用于追溯。旧地址退役由站长后续发起的遗留清理任务安排。

## 已比较的方案与取舍

- 完整拆出所需实现并由独立仓库持有构建和发布，满足后续单独维护的目标。共享实现或共享构建会继续要求跨项目协调，站长选择了完整拆分的边界。
- 快照起步保留迁移时的完整产品状态，博客仓库承担旧历史的追溯。将相关 Git 历史抽取到新仓库的方案未被采用。
- 旧地址采用过渡期对应跳转，已有收藏与分享可在过渡期继续访问。退役时机由后续清理任务确定。

## 代价与边界

- 路径从 `/books/` 改为 `/nice-books/`，涉及页面、数据请求、内部导航、canonical、图标及测试中的路径假设。
- 博客和 Nice Books 分别维护所需工具与资源的后续变更。
- 新仓库的历史追溯以迁移快照为起点，早期修改需回博客仓库查询。
- 旧地址退役日期由后续遗留清理任务确定，过渡期持续提供对应跳转。
