# 0012：Satori 升级定在 0.63.2，用两处显式盒模型声明换取可复原的几何

## 背景

README TODO「进行中」第三条挂着 Satori 0.26.0 → 0.63.2：跨 37 个 minor、74 条 release，上游既没有 CHANGELOG，也没有一条 release 标注 BREAKING。站点的 33 张 OG 分享卡全部由 `src/pages/og/[...slug].png.ts` 调用它渲染，而这条路由只产出 PNG，不写任何 HTML、CSS、JS。

隔离探针（[调研报告已归档](../history/history.md)，索引见「归档清单（第四批）」）把三个前置问题答完了：装得上、33/33 能渲染、**默认写法下每一张都错版**。本 ADR 记录据此做的取舍。

## 决定

**一、目标版本定为 0.63.2。不取中间版本，不冻结。**

**二、模板必须显式声明两处盒模型语义：根容器 `boxSizing: "border-box"`，标题行绿色竖条 `flexShrink: 0`。**

0.26 对 `padding` 的处理等价 border-box，0.33 起改为标准 content-box：`height/width: 100%` 配上 `padding: 60px`，根容器会从 1200×630 变成 1320×750，底部「作者｜日期」整行掉出 630 的画布。同一次变更里，标题行溢出时 flex 收缩的承担者也换了——0.26 让标题吸收，0.33 起让竖条吸收，竖条被压到 3–4px，标题多出同等宽度，断行随之改变。

这两处声明在 0.26.0 上**逐字节无操作**（33 张 PNG md5 全等）。它们不是「为升级打的补丁」，而是本来就该写、只是被 0.26 的默认值掩盖了的显式语义。

**三、验收用「像素差 0.2%」作阈值，不以哈希相等作判据。**

0.2% 是量出来的：同机同输入两次构建 33/33 逐字节相同；线上（CI 的 Linux）与本机构建 29/33 相同，4 张差 0.017%–0.028%；升级带来的最小真实变化是 0.71%。信号比噪声大一个数量级，阈值取在中间。

**四、执行形态：独立分支 + 独立 worktree，两笔提交（模板修复 / 版本升级），一次部署，走 PR。**

两笔的理由是回滚单元不同——模板修复对 0.26 无操作，依赖变更才是风险源，混成一笔会让回滚把两者绑死。一次部署的理由是 no-op 已被逐字节证明，为它多付一次生产发布不值。走 PR 的理由是让 CI 先在 Linux 上跑一遍真实构建，失败时线上不受影响。

## 被否掉的方案及理由

**0.32.0（HarfBuzz 之前最后一个版本）。** 实测产物与 0.26.0 **33 张逐字节相同**，能同时满足「升级」与「零变化」，是这个取舍里唯一的干净解。否掉的理由是收益近零：它带来的 webp 原生支持本站用不上（头像仍走 sharp 转码，而 sharp 反正要把 SVG 转 PNG）、SSRF 加固对只喂 data URL 的场景没有意义、`corner-shape` / `backdrop-filter` 全站未用；代价只是把「落后 37 个 minor」换成「落后 31 个」，上游依旧没有书面依据。

**冻结 0.26。** 零风险，也零收益；0.26 已 7 个多月未更新且无 CHANGELOG，越晚越难追。

**一笔 commit 全包。** 见决定四：回滚单元会绑死。

**抽样验收（只看最差几张）。** 否掉——这次升级的产物就是那 33 张图，抽样等于放弃唯一能证明「线上真的换了」的机会。

**顺手改用原生 webp 头像。** 否掉——会改变输入。这次的原则是「只换引擎、不换输入」，任何额外的输入变化都会让「17 张会变」这个数字失去解释力。

## 代价与边界

- **17 张 OG 图会变**：16 张换行点不同（多数是放下更多字、少截断），1 张整体下移 10px（全站唯一无描述的文章，空串子节点在 0.63.2 不再占 `gap`）。
- **页面 UI 不受影响，这是结构性的**：该路由只写 `/og/<slug>.png`，不参与任何页面产物的生成，也不需要靠「看起来没变」来保证。
- **跨环境不能比哈希**：同一份代码在 CI 与本机可产出不同字节（4/33 张，差异 ≤0.028% 像素）。
- **OG 图依赖构建期从 `fonts.googleapis.com` 拉到的字体**，网络抖动会让构建失败。这是既有问题，处置见 [`docs/agents/commands.md`](../agents/commands.md)。
- **`Cache-Control: immutable` 是写给自己看的**：`dist/` 里没有 `_headers`，GitHub Pages 不消费路由里设置的响应头，实际按自己的 `expires`（实测约 50 分钟）走。「旧图被永久缓存」这个担心不成立。

## 守卫在哪

`src/pages/og/[...slug].png.ts` 里的 `boxSizing` 与 `flexShrink` **看着冗余，删了会坏**：前者不写，画布变 1320×750、底部整行消失；后者不写，竖条被压到 3px 且标题重排。两处都带「为什么」注释，改这个文件之前先读注释。

### 实测结果

**一、OG 图：33/33 全部超过 0.2% 像素阈值，最小 0.71%、最大 9.95%。**

本 ADR 决定三把 0.2% 当成「有变化 / 没变化」的分界线，实测证明**这个用法不成立**，需要更正口径：

- 0.2% 的正确用途是**排除环境噪声**（跨环境实测上限 0.028%，阈值是其 7 倍），它能回答「是不是同一份产物」，不能回答「变化是否有视觉意义」。
- 原因是数量级不对：HarfBuzz 的字形漂移本身就带来 0.71%–2.8% 的像素差，全部高于阈值。阈值卡在噪声与字形漂移之间，却低于**所有**真实像素差，所以一张也筛不掉。
- 有意义的分类是变化性质，不是像素占比：**17 张结构性变化**（16 张标题换行点改变 + 1 张无描述文章 `20260320000000` 整体下移 10px）+ **16 张仅字形亚像素漂移**（版式与断行完全一致，差异图上只有文字轮廓）。
- 后续用这张票时，「17」指**结构性变化数**，不是「超阈值数」。更正已留在 #144。

**二、页面零回归，判定口径是「稳定集内零差异」，不是「零差异」。**

整站构建非确定——同状态两次构建就有 146–156 个 HTML 不同（构建期随机文章列表）。用**三份**同状态 0.26 构建求稳定集：两两差异 146 / 156 / 156，抖动集 |D| = 156，稳定集 |S| = 787；升级后与基线的差异 |U| = 156，**全部落在 D 内**，稳定集里的升级差异为 **0**。脚本 `output/satori-upgrade/non-og-verdict.mjs`（可复算）。

注意单次两两比较会低估抖动集（146 < 156），拿 146 当分母会造出 10 个假回归（about / albums / friends 等含随机文章列表的页面）——判定必须用多份同状态构建的稳定集。

**三、构建链与断言全绿：** 230 个 HTML、33 张 OG；`node scripts/verify-og-images.mjs` 33/33（最小非白像素占比 4.199%）；KaTeX 类名校验通过（旧类名 0 个、新类名 1338 个）。

### 与 ADR 正文的偏差

- 决定四写的是「两笔提交」，实际是三笔——`6d80662` 的产物断言单独成一笔。回滚单元没有变化：断言不改变产物，`999d3f8` 仍是唯一的风险源。
- 决定三的阈值用法见上，结论不变（该路由与页面产物无关，升级风险仍然只有那 33 张图），变的是判据的读法。
- 票面把数量写成「恰好 33 张」，`6d80662` 照此写死成常量，等于给下一篇非草稿文章埋了一个假红灯。**2026-11-05 已改为派生**：期望数量 = `src/content/posts/*/index.md` 中 frontmatter 不含 `draft: true` 的篇数，与 `getStaticPaths` 同源。判据强度不变（少一张、多一张、白板、错尺寸仍全部报错），只是不再需要人工同步这个数字。
