# 侧栏文章目录：与文集目录共用一个粘性栈

文章页的侧栏原本只有文集目录是粘性的。长文（实测全书最长一篇有 62 个标题）里，读者翻到下半篇想跳章节，必须先滚回顶部再用正文顶部的目录——我们决定增设一个侧栏「文章目录」，放在文集目录之下、跟随滚动常驻，并让它的激活态跟随当前阅读位置。

两个都做成独立粘性兄弟是行不通的：实测同一侧栏内两个粘性元素各钉在相同的视口偏移上，滚动后互相压住 **87.9px**（前者 10–230，后者 142.1–342.1），后者最终整块盖住前者。因此两者必须**共用一个粘性容器**。

共用容器又带出第二个问题：两个小部件的固有高度之和会超过矮视口。实测 **360px** 高视口下，固定高度方案的外壳高 424px、超出视口，且列表滚到底时最后一条仍在视口之外；把外壳改为「视口高减去上下留白」的弹性高度、并给容器链上的每一层补 `min-height: 0` 后，900/720/500/360 四档全部装得下。

## Considered options

- **两个独立粘性元素、给第二个写死偏移**：省一个容器，但文集目录高度随成员数变化（4 章与 2 篇不同），写死偏移一加章就错位。
- **把文章目录并进文集目录那个小部件**：不新增组件，但两者数据来源不同（一个是文集成员，一个是当前文章的标题树），合并会让一个组件有两个不相关职责。
- **只让文章目录粘性、文集目录回到普通流**：改动最小，但会牺牲文集目录既有的粘性收益，等于用一处改进换一处退步。
- **固定列表高度上限、不做弹性归一**：写法最省，实测 360px 视口仍溢出——溢出的根因是两个小部件固有高度之和大于视口，只压其中一个不够。
- **删掉正文顶部那份目录、只留侧栏**：消除同页两份目录的冗余，但在本站 ≤980px 的断点上侧栏整体隐藏，移动端会因此彻底失去目录入口。

## Consequences

- **两个小部件从此共用同一个粘性容器**，粘性行为在物理上无法分开验证。因此侧栏粘性的回归判据扩写进既有的文集烟测脚本，而不是新开一个脚本——否则同一段几何会被两处断言。
- **正文顶部与侧栏是同一份内容的两种放置**，同源同序，只容许在容纳方式（顶部可折叠、侧栏内滚）与激活态（顶部无、侧栏有）上不同。**改动一处须同步另一处**；术语边界记在 `GLOSSARY.md` 的「文章目录」条。
- **侧栏目录的激活态是本站第一处 scroll-spy**。此前所有「当前态」都是构建期判定的（文集目录的当前章就是按 URL 直接比出来的）。这条计算只能运行时做，因此 swup 切页后必须重新采集——实测切页后标题数会从 61 变 46 而滚动位置归零。
- **矮视口下的可用性由既有烟测脚本的 360px 专用视口守住**。该视口本就是为粘性判据准备的，新增的弹性高度判据挂在同一处。
- **弹性归一给共享的容器链补了 `min-height: 0`**。这是弹性布局的必要条件（否则子项不肯收缩），不是引入新的设计语言。
- **激活态在第一个标题越过判定线之前不点亮任何条目**。实测初载与 swup 切页后首个标题都在视口下方约 1100px 处；此时「没有正在阅读的章节」是真实状态，不是未定义行为。
