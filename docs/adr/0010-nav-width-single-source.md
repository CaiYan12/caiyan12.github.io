# 0010：导航宽度收敛为单一真源，挂件横向锚点由 CSS 自算

2026-11-02。拉绳壁纸挂件（`src/components/control/WallpaperPull.astro`）重做视觉后，横向锚点定为「中心线压在 `#head-nav` 右缘」。

问题在于：挂件是 `position: fixed`、挂在导航**之外**，CSS 读不到另一个元素的宽度；而它的首帧又必须落在正确位置（运行时写 `--wpull-left` 要等 `pagefindReady()`，实测首帧 140ms、写入 370–395ms，中间 240ms 是空的）。于是挂件的 CSS 兜底只能把这个位置**再算一遍**——它天然是第二份真源。

决定：导航宽度只在 `global.css` 的 `:root` 定义一次——`--nav-w`（宽档固定宽 1100px）与 `--nav-side`（窄档两侧留白 20px）；`#head-nav`、`#header .box`、`.wpull` 三方只消费这两个变量。挂件的兜底写成三选一 `min(50% + --nav-w/2, 100% - --nav-side, 100% - 盒宽/2 - 8px)`，**不带断点**：断点邻域的歧义区间里第三项（视口边距夹取）必定更小，`min()` 取到的就是正确答案，所以导航的断点改了挂件也不会脱钩。

反例说明为什么不能用别的方式：

- **挂件里硬编码镜像 1100/40**：这正是被修掉的形态。两处字面量一漂移，首帧就落在错位置再闪过去（实测 1440 档偏 103px、1170 档偏 187px）。
- **提前同步执行 JS**：只能缩短闪动窗口，不能消除——窗口里画的仍然是错值；且组件在 `#head-nav` 之前渲染时读不到导航。
- **把挂件挪进导航的定位上下文**：挂件钉在视口顶边，与导航不在同一视觉带，改结构代价远大于收益。
- **JS 只写、CSS 不给兜底**：首帧会落到 `left: auto`（即 0），闪动更严重。

代价与边界：`--nav-w` 只对宽档生效（窄档由 `--nav-side` 决定，导航自己的媒体查询就是这样写的）；`min()` 三项里只有第三项真正兜底，前两项是「导航右缘的两种算法」。恢复旧实现需同时回退 `:root` 的两个 token、三处 `width` 与 `.wpull` 的 `left`。

守卫在 `pnpm smoke:wallpaper-pull`：①「首帧定位 = 落定定位」（1440 / 1024）；②「改 `--nav-w` 后导航确实变宽，且挂件首帧仍等于落定值」——注意它**不硬编码期望坐标**，否则等于把被测几何再抄一份。相关实测记录见 `docs/agents/styles.md`「导航宽度的单一真源」与 `CHANGELOG.md` 2026-11-02 条。
