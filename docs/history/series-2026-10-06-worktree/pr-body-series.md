# 文集（series）——同主题文章的封闭阅读序列

把「文集」立为与标签、分类并列的**独立轴**，让同主题文章拥有一条自己的、封闭在组内的阅读序列。批次集成分支 `feat/series`，由 10 张票顺序叠加而成。

## 为什么

文章页的左右按钮由 `getNeighbors()` 在**一条全站时间线**上取相邻项（`src/utils/content-utils.ts`），于是《看懂 AI 写的网站》四章在导航上不是一个整体：第三章的右按钮指向不属于本书的 Matt Pocock 那篇，Matt 篇的左按钮又落进本书第三章。访客既看不出「这是一组有顺序的文章」，也没法把整组读完。

方案要点：

- 成员资格与组内序号都写在文章的 frontmatter（`series` + `seriesOrder`），归**只有这一处记录**；文集名 / 简介 / 量词放 `src/data/series.ts`。
- **判定层不查登记表** —— 有 `series` 属性即属于某文集。写了未登记的 slug 是**内容错误**，由构建期校验响亮报错，不是判定降级。
- 组内边界不渲染该方向的按钮；**非成员文章的导航跳过整个文集**（刻意为之，ADR 0007 有记录，勿当缺陷修回）。
- 进度分母取已发布成员数，不引入计划总章数。

## 测试缝

- **缝隙 B（纯函数）**：逻辑全部落在既有 `pnpm test:utils`（已在 `pnpm build` 链头，push 上是真门禁）。
- **缝隙 A（接线冒烟）**：新增 `pnpm smoke:series`，复用既有 `scripts/lib/smoke-harness.mjs` 的 `makeHarness`，**不往既有 `smoke:ui` 里加判据**（其 121 项被 `#49` 当基线引用过）。
- 每一票都要求**红证据**（先真翻红、记录输出、再还原），沿用 `#49` 立下的测试文化。

## issue 的关闭方式

各票的 mirror issue（#77–#86）在本批次里**逐票**关闭，关闭时附该票的 commit。因此本 PR 正文**不使用** `Closes` / `Fixes` 关键字，避免合并时批量误关。

## 边界

- 本分支**不动 `main`**：推送 `main` 会触发完整构建链 + GitHub Pages 公开部署，须站长单独同意。
- 校验刻意不做独立 `.mjs` 脚本（仓库无 YAML 解析依赖，手写正则的失效模式是**静默漏读**），改为纯函数由路由的 `getStaticPaths` 调用并 `throw`。
- 刻意**不**把 `src/data/series.ts` 的 `cover` 缺省回退简化成既有 `getCover()`：后者的兜底是按 slug 取模选出的**无关随机缩略图**。
